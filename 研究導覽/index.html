    本輪整理：2026-11-02；材料窗口：2026-10-02 至 2026-11-01。 巡檢兩份年度索引，回讀下列精選的既有 Markdown；沒有重新查證外部消息、補讀論文原件或重跑實驗。原文、版本與實讀範圍以單篇為準；較早的摘要／導論筆記不因被串聯而升格為方法閱讀。這是材料窗口，不表示期間每天都有產出。

    工業／實體 AI：從展示到可靠部署¶

    1. 局部成功，何時才算交還一段工作？¶

    • 事件入口：GXO 擴點與換代成本 → 便利店的整段補貨與人力回收。前者新增既有客戶的擴點規劃，後者仍是未定啟動日的試驗方向；兩者都不能直接填成已驗收的節省工時。
    • 方法對讀：PIFR 的階段與整鏈分母 → RESCUE 的介入價值。恢復入口段成功不等於全鏈成功，警報辨識也不等於恢復划算；這是評估問題對照，不代表新聞中的產品採用了這些方法。
    • 修正與下一證據：將舊「可替換產能」判準收緊為完整批次／班次的合格交付、人工救援與排班回收，再另測跨站及換代成本。看實際啟動後的首個完整營運週期，不以累計動作量替代對應工時；安全不拿來折抵經濟收益。

    2. 表徵有用，是訓練支架、部署讀取，還是內容真的改變決策？¶

    • 精選順序：IMEP 的配對內容介入 → ThinkWorld 的訓練支架 → HiFOR 的部署檢索。先學如何問「使用」，再比實際資訊路徑；不依主榜平均排名。
    • 修正了什麼：不能一概說未來 tokens 只在訓練有用；HiFOR 提供部署直接消費預測 latent 的路徑。但直接消費不等於內容特異性，更不等於逐候選重算後果。ThinkWorld 的生成 CoD 不直接進部署動作專家，仍保留原判讀。

    • 未解與驗證：固定資料、監督及算力，做同事實／異事實內容替換、同程序安裝控制與固定 query 對照，分報替換送達、決策改變、完整任務結果。IMEP 未在上述兩模型完成這套測試，不能把跨篇提案寫成已有結果。

    • 後續方法閱讀補註（2026-11-02，非上列月度回收範圍）：CoRAct 的離線後果對齊補上另一條資訊路徑：訓練時對各候選動作預測後果、更新噪聲策略，部署只取一個初始噪聲，不再在線重做候選後果驗證。這與 HiFOR 的部署直接檢索不同；下一證據應是 reward 排序對真實執行的校準，而非只看預測 waypoint 誤差。不把更忠實執行錯誤 ECoT 視為任務正確，亦未改寫舊文閱讀範圍。

    • 後續方法閱讀補註（2026-11-07）：動作 token × 梯度路由補上 backward 學習路徑：動作 tokens 在部署不解碼，仍可能在訓練中替代部分 expert-to-VLM 梯度訊號；stop-gradient 也不是凍結整個 VLM。這把「訓練支架」細分為哪些 loss 教誰、關掉後還剩何種控制監督。本文是模擬單 seed 的配方對照，不是表徵內部機制證明；下一證據為等元件更新／loss 尺度、多 seed、廣泛能力保留與真機完整成功，進度與安全仍須分報。

    • 後續方法閱讀補註（2026-11-12）：Memory Clock 的時間捷徑把「模型使用歷史」再拆成事件事實、顯式時間戳與隱式槽位配置；去掉時間編碼不代表去掉時序捷徑。事件索引能排除部分空動作，卻可能刪掉返回相同場景的真實工作，故「物理返回」不等於「任務等價」。下一證據為固定槽位的內容介入、含噪真機事件辨識及乾淨任務損失；本文與 IMEP 只作方法對讀，尚未驗證整合，不外推所有記憶模型或改寫舊文閱讀範圍。

    3. 新資訊何時失效，舊命令又能否被取消？¶

    • 精選順序：Chronos 的物理時間介面 → OpenFlyV2 的記憶、快取與命令承諾 → BT-Agent 的固定技能與本地 guard。依序問資料年齡、未來已承諾動作、模型外停止權。
    • 判準收緊：快取內容、單輪 KV 重用與 committed action prefix 有不同有效期；局部去噪變快不證明整輪新鮮，命令歸零也不證明實體停止。Chronos 不是 LLM 語言推理研究，不能直接借成 VLA 整合效果。

    • 下一證據：分測擷取到生效的尾延遲、時鐘偏差、過期動作丟棄與 prefix cancellation，再量物理停止／完整成功。三篇提供不同接口，尚未組成已驗證的整合安全系統。

    • 後續方法閱讀補註（2026-11-05）：VLALagBench 的時序分帳新增同步與 lazy async 的對照：平均觀測年齡相同，停頓不同，任務成功仍可能改變；continuous 則用更多請求換更新頻率。這把「資料新不新」收緊為年齡、運動連續性、chunk 後段品質與每台請求預算的聯合問題；本文也有高延遲下同步反勝、過早開夾爪等反例。與 Chronos／OpenFlyV2 僅作介面問題對讀，未驗證整合，下一證據是固定牆鐘期限與延遲抖動下的完整成功及切段失敗。

    • 後續方法閱讀補註（2026-11-06）：ARP 的過期語意訓練將「非同步」再分成整模型／chunk 排程、慢語意與快視覺分流、prefix 交接三層。同架構 cache-age 消融支持訓練要涵蓋部署錯配；並不證明記憶有前瞻能力，也沒有驗證新指令撤銷。下一證據是固定算力與多視角的因子比較、延遲抖動與指令切換下的完整成功；真機進度分數、18 任務子集與完整 RoboLab 分開閱讀，不把局部效率推成全面超越。

    AI 基建與產業經濟：承諾、瓶頸、地方成本¶

    4. 客戶承諾究竟替哪一種風險付了錢？¶

    • 精選順序：京元電預付款的雙邊承諾 → 是方的簽約、進駐與損平 → 諾基亞的調整獲利與現金。按權利／義務、使用、全成本及現金讀，不把不同公司的帳加總。
    • 修正了什麼：不只保留「設備支出不是需求終點」的否定句；具名客戶預付款協議比單邊擴產更接近雙邊承諾，但未見收款與完整條款，仍不能量化風險移轉。諾基亞的新季度材料則要求把能力重估拆成 comparable、reported 與現金三種財務兌現。
    • 下一證據：在各公司下一次披露核對收款、取消／最低付款、交付與全成本；是方的「五成／滿租」與損平定義仍未解，諾基亞完整調節表仍待補讀。不用集團總營收填補專案未知。

    5. 模組化消除了瓶頸，還是把整合移到另一個地方？¶

    • 事件入口：DSX POD 的工廠與場址時鐘 → 回看資料中心的承諾與使用。這是機制對照，不代表是方採用 DSX POD。
    • 第一性約束：工廠製造、場址接電、接合驗收、付費負載各有時鐘；局部提速只有動到總關鍵路徑，才提前整體交付。前置驗證可能減少現場返工，卻也把責任和成本移向整合商，不能先當成本消失。
    • 下一證據：首批具名案例分記場址就緒、出廠、現場驗收與付費負載，在可比容量／條件下看返工與總工期。「最快14天」不是投資到營運的總工期；地方資源與責任約束仍參照社會科學的第一性原理，不以工程提速跳過制度成本。

    Agent 治理：授權、行動、稽核¶

    6. 合法介面，如何走到現場可採信的行為？¶

    • 精選順序：Nav2 的政策合法、語意正確與物理守界 → 機器人標準的介面、範圍與採信。從單一 bridge 的提交，走到跨公司規格；只比較責任邊界，不主張兩者有技術採用關係。
    • 修正與保留：在舊「誰允許、誰執行、誰回滾」之外，加問指令是否被忠實翻譯、提交是否送達、下游是否物理遵規。validator 與通信標準各自有範圍，不能承包沒收到的語意或未規範的安全責任。

    • 下一證據：同一正確政策比較 GUI／規則／LLM 輸入，另測漏限制、送達延遲與撤銷；跨廠實作要看取消、失聯、版本差異及客戶驗收。授權、稽核與責任仍接回代理行動帳本；該舊文未因本輪被改寫或重新查證。

    • 後續方法閱讀補註（2026-11-03）：VLA 啟動抑制再分開「選擇哪個任務」與「是否應開始」：首輪動作因語言改變，不等於有可執行且獲准的意圖；負例微調未完成任務，仍可能累積漂移。下一證據是獨立場景校準、誤放／誤擋及持物等待／撤銷測試；本文僅單布局模擬，不把 gate 或 5 公分 non-start 當成實機安全保證，也不推稱已和 Nav2 整合。

    • 後續方法閱讀補註（2026-11-13）：LEASH 的三層審核把「獲准行動」拆成目標、候選 skill 與不可逆操作；有限範圍的批准不等於有時間到期／撤銷規格，更不等於 skill 全程物理安全。它也新增統計邊界：只看已通過且執行的候選，不能推算危險提案攔截率；共享政策與 gates 同時加入，需因子消融才能歸因。與 Nav2／啟動抑制僅作責任接口對讀，下一證據是 policy-only／gates-only、被拒候選反事實標籤與批准後場景改變的阻擋尾延遲，尚未驗證跨篇整合。

    跨材料的共用工具¶

    新增從局部改善到系統收益的證據交接：每跨一個接口，補問「傳了什麼、是否仍有效、下游是否使用、最後誰拿到收益／承擔成本」。這是本輪跨材料整理的檢查工具，不是跨領域共同定律；原有社會科學的第一性原理仍負責提醒激勵、資訊不對稱與交易成本。

    如何持續整理¶

    同一事件或同一警語不逐日疊加；只有新增機制、推翻條件或不同證據層才進路徑。其餘材料保留在年度／日期索引，不搬檔、不改舊文事實。下一輪優先查上述缺口是否有新證據，沒有就維持未知；寫作與閱讀標準見編輯規範。
