    PEAR：模擬學會位姿決策，不等於免除控制器與任務覆蓋¶

    問題：不用機器人示範資料，能否靠模擬中的成功／失敗，把開放權重推理模型教成可遷移的 robot-use policy？ 方法：模型讀相機、機器人狀態及歷史，輸出位姿增量；外部控制器完成動作後才回看。RURL 用二元終局獎勵及分階段課程更新整段推理與動作 tokens。 判讀：學到新機體可用的位姿決策有實驗支持，但「無 harness」不代表無控制器；真機 18/30 是兩類任務的遷移，不是任意工作的泛化，更不是快速或安全部署證明。

    1. 缺口不是模型不會說，而是不會把空間判斷變成下一步¶

    作者區分兩種控制路線：VLA 以任務示範微調動作模型；robot-use agent（RUA）則讓通用視覺語言推理模型直接產生下一個末端位姿。後者可利用語言及世界知識，但開放權重模型在這些任務上初始成功率很低；外加感知工具、抓取技能與 planner 又會限制可選行為。

    PEAR 的改動不是再建一套技能庫，而是把「觀察—推理—位姿—執行—再觀察」做成可大量收集的 RL episode，以模擬器的成功判定更新模型。這裡的無示範，指這次 robot-use 後訓練沒有加入示範／SFT；不代表基礎模型的預訓練沒有資料，也不代表提示與控制介面不提供先驗。

    值得研究的是：如果外部介面保持同樣的位姿語言，模型是否學到跨機體的決策，而不是背誦某個模擬器的動作？因此應一起讀跨機體、完整 benchmark 與控制器限制，而不只看 LIBERO 平均分。

    2. 任務、輸入輸出與真正的控制迴圈¶

    依 §3.1、附錄 A、H：

    1. 輸入：任務指令、描述相機／座標軸／機體的 system prompt，當下相機影像及 JSON 機體狀態；此前各輪觀察、推理與動作保留在 context。
    2. 輸出：推理文字加一個 JSON 動作，對每個 named part 的每個 quantity 列出增量；長度單位公分、角度弧度，未改變量寫零。不是模型直接輸出關節力矩，也不是一次規劃完整 action chunk。
    3. 執行：由外部控制器把目標實現；LIBERO 使用 Franka 的 operational-space controller，RoboDojo ARX 以 Cartesian waypoints 與逆運動學執行。真機同樣由機體自己的逆運動學與控制器負責。
    4. 回看時機：達到目標且機體靜止，或受阻而停止後，才回傳下一輪觀察。這是逐位姿、走完再看的閉迴路，不是語言模型在動作途中持續高頻修正。
    5. 終止：模擬器報成功、達 step／context 預算，或回覆沒有有效動作；真機另設最多 25 輪、單輪推理上限 32k tokens，逆運動學無解的重試也算一輪。

    相對基線真正保留下來的外部能力：不供應 segmentation、抓取／motion planner 或技能庫，但仍有座標說明、機體狀態、影像、動作解析、控制器、停止行為和任務結束機制。附錄 H 甚至明說「只要還有觀察，任務就尚未完成」，因此模型不是單憑自己生成的文字自主驗收全部成功。

    本筆記判讀：可把高階技能選擇內化到模型，卻不能把執行層成本當成消失。跨機體的共同 JSON 介面，轉移的是命令表達與部分決策；不同控制器如何實現位姿，仍會影響精度、平滑度與剩餘動作預算。

    3. 學習訊號：終局成功，同時教推理與動作¶

    二元 reward 與組內相對優勢¶

    以簡式重述 §3.2 的目標：

    \[ \max_\theta\;\mathbb{E}_{\tau\sim\pi_\theta}[R(\tau)],\qquad R(\tau)\in\{0,1\}. \]

    \(\theta\) 是模型參數；\(\pi_\theta\) 是依完整上下文產生回答的策略；\(\tau\) 是一整段觀察與回答軌跡；\(R\) 由模擬器判定整段是否成功。白話是提高「整件事做成」的機率，不是逐步評分推理是否正確、碰撞是否少或耗時是否短；那些未列入 reward 的代價不能自動視為已最佳化。

    同一任務及初始狀態抽樣 \(G\) 條 episode，作者使用 GRPO 式組內標準化：

    \[ \widehat A_i=\frac{R(\tau_i)-\overline R}{s_R+\epsilon}. \]

    \(i\) 是組內第幾條軌跡，\(\overline R\) 和 \(s_R\) 分別是該組 reward 平均及標準差，\(\epsilon\) 是防止除零的小常數。成功與失敗混在同組時，模型才知道哪些回答相對較好。同一 episode 的所有生成 tokens，包括每輪推理及動作，都使用同一個優勢；不是額外標出哪句思考或哪一步動作真正造成成功。

    實作並非照抄完整 clipped GRPO：採 REINFORCE policy loss、token-mean，無 PPO clipping、KL penalty 或 entropy bonus；非同步 rollout policy 落後訓練 policy 一至兩版，以 score-centering 校正，不加 truncated importance sampling。全成功／全失敗組依 DAPO 式 group filter 丟棄重抽。這些是原文配方，本文不把校正效果當作已有單獨消融證明。

    課程是在解決「連一個成功都抽不到」¶

    作者先用 LIBERO Goal／Spatial／Object 訓練 148 steps；第 149–225 steps 加入 Long；再由 LIBERO-only checkpoint 在 RoboDojo 的 general_pickup、align_blocks 訓練 115 steps。它不是把整個 RoboDojo 任務庫都均勻學完。

    附錄 A 設定每 step 在過濾後保留 128 組、每組 8 rollouts；AdamW learning rate 為 \(10^{-6}\)，即每次更新使用的步長設定，不是精度保證。最長序列 LIBERO 256k、RoboDojo 160k tokens，全程 xhigh effort。訓練總量約 50,000 H100-equivalent GPU-hours，屬作者的折算口徑；無示範不等於資料產生與計算便宜。PEAR 以 veRL 非同步收集／更新，配合 prefix KV cache、CPU offload、分散式與序列平行處理長 episode；GB300 設定因 host memory 條件不使用 LMCache。

    本筆記的簡化分析：假設固定初態下各 rollout 獨立且成功機率同為 \(p\)，組內出現成功與失敗的機率為

    \[ P_{\mathrm{mixed}}=1-p^G-(1-p)^G. \]

    \(P_{\mathrm{mixed}}\) 是有非零相對學習訊號的組比例，\(p\) 是單次成功率、\(G\) 是組大小。取 \(G=8\)，若 \(p=0.004\)，約僅 3.16%；若 \(p=0.39\)，約 98.03%（Python 計算）。這借用了 Long 的前後成功率作直觀示例，不是作者量測的訓練接受率：實際不同初態的 \(p\) 不同，且 rollout 未必滿足獨立同分布。它解釋了為什麼先從可成功任務轉移，再納入難任務，可能比盲目加大難題抽樣有效。

    4. 實驗支持到哪裡：分母、對照與反例一起看¶

    已有支持的三層證據¶

    • 在原任務學會控制（§4.1、Table 2）：LIBERO 40 任務、每任務 50 episodes，總 2,000；LIBERO-only 模型成功率由基礎模型 1.6% 到 74.4%。未訓練 Long 時已達 Long 39.0%，其後加入訓練到 53.2%，為課程的轉移入口提供觀察證據。
    • 不只複誦場景對應動作（§4.2、Tables 3–4）：LIBERO-Pro 的 task perturbation 固定熟悉場景但換任務，每種擾動對本方法 2,000 episodes。本文 57.4%，對照示範微調的 \(\pi_{0.5}\) 為 0.75%；這裡 \(\pi_{0.5}\) 是模型名稱，不是數學機率。四種擾動平均 62.1% 對 53.3%。但語句改寫及物件換外觀仍由該 VLA 領先；不能概括成所有 robustness 都更好。Table 4 含未擾動任務的平均口徑又不同，不能把 64.5 與只算四種擾動的 62.1 混用。
    • 新機體的真機遷移（§4.4、Table 7）：真實雙臂 YAM 每個模型共 30 次；10 次用三角尺推齊三個積木並放開、復位，20 次為十種物件各抓兩次、抬高 10 公分。基礎模型 0/30、LIBERO-only 7/30、最終模型 18/30。最終模型訓練雖沒見過 YAM／真機資料，卻在 RoboDojo 見過這兩類任務，故是跨機體／模擬到真實的遷移，並非同時證明任務類型全新。

    不能被主榜掩蓋的覆蓋缺口¶

    附錄 E 是本篇重要的限制證據：完整 RoboDojo 有 42 任務、54 task settings，每 setting 十次共 540 episodes；最終模型只完成 21 次，其中多數在兩個訓練任務。370/540（作者報 68.5%）因 256k context 耗盡失敗。官方總分是五個能力維度的平均，21/540 的原始計數不能直接當官方榜單分數。只引兩個訓練任務的高成功率會遮掉長任務覆蓋不足。

    RoboLab-120 每任務十次，最終模型取兩輪評估平均；Table 5 的總成功率為 37.3%，但 complex 類僅 13.2%，Cosmos3-Nano-Policy 為 25.3%。RoboLab 的 Score 是可給子任務進度分的另一指標，不是成功率；其他模型是作者引用的 DROID checkpoint 榜單資料（2026-10-29），不代表已同硬體、同動作頻率重跑。

    消融與公平性¶

    • xhigh 降到 low effort：每輪 thinking tokens 3.23k 降至 0.86k，LIBERO 成功率 74.4% 降至 21.9%（low 為兩次評估平均）。支持推理預算對這個模型有影響；不證明長文字的語意推理是唯一因果來源，仍缺固定計算／控制步數的 no-CoT 對照。
    • 同基礎模型前後、LIBERO-only／最終 checkpoint 的比較有價值；但增加 RoboDojo 同時改變資料與訓練量，不能把差額全歸因某一種機體知識。
    • \(\pi_{0.5}\) 結果由 openpi／先前研究引用，作者沒有自行重跑；兩路的訓練監督、預訓練與計算預算也不同。它是能力比較，不是隔離「RL 天生優於 SFT」的因果試驗。
    • 本次已讀部分未提供同預算 SFT、課程／group filter／score-centering 各自移除的完整因子消融，亦未見多個獨立訓練 seeds；不為缺失欄位補結果。
    • 九個通用基準的 paired bootstrap 95% intervals 都含零（Table 6），只表示在該題集／樣本量下未測到明確差異；不是預設等價界線後證成「完全不遺忘」。

    5. 效率、失敗與安全必須分帳¶

    作者在 §4.6 報單 GB300、NVFP4 加 drafter 可到 747 tokens/s，並估 xhigh 每輪約 4.3 秒；任務成功率評估使用 BF16，因 NVFP4 會降低準確率並拉長推理。因此不可把 747 tokens/s 與 74.4% 拼成同一個已驗證部署點，更不能把純 decode 時間當整輪感知、prefill、執行、等待及安全驗收延遲。

    附錄 G 真機逐次記錄顯示：最終模型的十二次失敗含六次耗盡輪數、三次積木未對齊、兩次撞倒物件、一次網球滾走。LIBERO-only 還有兩次 unsafe pose 自動停止。最終模型這個樣本沒有該失敗類型，不表示有持續安全保證；論文沒有在這裡給出完整碰撞率、接觸力、急停尾延遲或外部人員介入的工程驗收規格。

    額外的畫畫及化學試劑選擇是示例，不列入上述 30 次分母；§5 並承認難任務要詳述機體與任務才成功。不能把示範影片式成果與有重複試次的成功率合成一個泛化百分比。

    6. 第一性原理：少掉的是技能包，不是物理執行成本¶

    最小必要狀態：指令、座標／相機與機體語意、目前末端與夾爪狀態、能確認物件與接觸結果的觀察，以及足以辨認前次錯誤的歷史。本方法用完整 context 保存歷史，但沒有證明每段推理都不可刪；context 用盡是整段工作未交還的實際瓶頸。

    有效條件：基礎模型對部分任務已偶爾能成功，才能用相對成功作梯度；模擬器成功判定足夠可靠；位姿介面與真機控制器能維持預期語意；任務容許逐位姿停下、等待下一輪推理。這些條件說明可遷移為什麼可能，卻不保證高頻接觸、動態物件或持續人機協作也能照搬。

    三種資源限制：模擬探索是否得到 reward、context 是否容得下完成工作、物理與牆鐘預算是否容許等待。只放寬 context 可能把耗盡記憶改成耗盡時間；只壓短推理又可能降低決策品質。應測整個成功—時間—風險前緣，而非各選一個漂亮數字。

    可複用模型：把所謂「直接控制」拆成四帳：模型內化哪些決策、介面保留哪些先驗、控制器負責哪些可達與停止、測試覆蓋哪些完整工作。與 AMP1、Reins可對讀：本篇把訓練訊號納入模型，並不替代另外兩篇關心的回看與恢復權限。這是問題對照，不主張已做跨篇整合。

    7. 後續可否證問題¶

    1. 真正轉移還是任務挑選？ 固定控制器與訓練計算，對全新任務族、prompt 改寫及新機體做因子評估，保留完整 RoboDojo 各維度分母；若提升只在兩個課程任務，應縮小泛化主張。
    2. 長推理買到什麼？ 固定牆鐘期限及可用動作次數，比較壓縮歷史、固定預算 no-CoT 與不同 effort；同報 BF16／NVFP4 的完整成功及尾延遲，不再拼接兩個設定的最好數字。
    3. 位姿可執行是否足以交還工作？ 對受阻、物件滾走、換指令與人員進入測試命令取消、外部停止和恢復；分報控制器拒絕、物理停止、人工救援及完整交付，不能用未觀察到 unsafe 代替安全驗收。
