    AgentRoboCritic：局部意圖履約，不等於全局任務正確¶

    問題：直接用多模態 agent 操作機器人時，如何分開「它本來想做什麼」、「動作有沒有做到」與「整件工作有沒有做對」？ 方法：每次數值動作附帶局部意圖，再用對齊的前後影像與必要的後續提起影像，評判局部履約與可見失敗類別；蒐集標註後蒸餾成較小 critic。 判讀：這是有價值的診斷介面，卻不是全局語意正確、安全或即時控制的驗證。尤其 Choice 的定義排除了「忠實執行錯誤局部目標」，不能用其稀少直接證明整體語意推理可靠。

    一、缺口：二元終局成功率，會把恢復與一路順利混在一起¶

    同樣完成一個任務，可能是每步正確，也可能失敗後反覆重抓。只看 episode success，無法知道瓶頸是選錯物件、沒抓牢，還是插接角度不足。反過來，某步看似沒前進，也可能是在測試抓握或做小幅調整，不該直接判失敗。

    本文把局部意圖變成評估參照：先固定這步要達成的狀態，再看可見物理變化。真正新增的不是另一個會輸出動作的控制頭，而是帶意圖的軌跡紀錄、接觸語意適配的觀測窗口、分類 codebook，以及人工核對與 critic 蒸餾。

    二、任務、輸入輸出與執行路徑¶

    1. Policy 同時交出動作和當步契約¶

    沿用 §3 的記號：

    \[ (a_t,g_t)\sim\pi(\cdot\mid G,O_t^{\mathrm{pre}},h_t). \]

    \(G\) 是整體任務，\(t\) 是決策回合，\(O_t^{\mathrm{pre}}\) 是動作前影像，\(h_t\) 是互動歷史；\(\pi\) 是 policy，\(a_t\) 是數值控制命令，\(g_t\) 是自然語言局部意圖。白話說，agent 不只交出位姿／關節／夾爪目標，也要說明這次預期的結果。這不表示自然語言已描述完整物理狀態或經過安全授權。

    實作把局部意圖設成工具呼叫的必填 note；漏填便拒絕該呼叫，要求重送。新蒐集七個 benchmark 的軌跡，另把五個已釋出的軌跡透過 adapter 對齊意圖、動作及影像。所謂 direct control 仍會經過執行 harness；數值命令由文字輸出，不等於繞過低階控制器或直接以語言模型頻率驅動馬達。

    2. Critic 評估已執行的狀態轉移¶

    \[ \mathcal O_t=(O_t^{\mathrm{pre}},O_t^{\mathrm{post}},O_t^{\mathrm{aux}}),\qquad (\hat y_t,\hat m_t,\hat e_t)=\mathcal C(G,g_t,\mathcal O_t). \]

    \(O_t^{\mathrm{post}}\) 是動作後多視角影像；\(O_t^{\mathrm{aux}}\) 是必要的短期後續影像，例如夾爪閉合後的提起；\(\mathcal C\) 是 critic，帶帽符號表示其預測：\(\hat y_t\) 是履約結果，\(\hat m_t\) 是失敗類別，\(\hat e_t\) 是簡短可見證據說明。這是主文 Eq. 3 的簡化介面；附錄 B 的實際輸入還包括命令及執行狀態，不能只按公式重製。

    結果區分 Achieved、Failed、Partial、Unverifiable；實際 schema 另含 not_applicable，處理拒絕執行或非機器人紀錄。Failed 才給 Grasp、Alignment、Interference、Effect、Incomplete motion、Choice 或 Unresolved；Grasp 再細分接觸／掉落時點。看不出是否成功與確知失敗但不知原因是兩種不同狀態。

    關鍵流程是「產生意圖與動作 → 執行 → 對齊證據 → 事後局部評判」。抓握不以夾爪閉合當作抓住，要看提起後是否保有物件。提示也明言選幀不等於連續影片，不能從影像發明摩擦、隱藏力或校正問題。這些是標註規則，不代表 critic 每次都能遵守。

    3. 訓練的是 critic，不是用該資料再訓練主 policy¶

    附錄 F：critic 資料來自 2,027 個 episodes，只保留具有完整前後影像、且已判 achieved／failed 的動作，按成功一份、失敗三份抽樣；按 episode 切分，避免同一 episode 的動作跨集合。

    • 訓練：12,844 動作（3,211 achieved、9,633 failed）。
    • 驗證：1,548；測試：1,936。主表的 400 人工標註動作取自 test split。
    • 輸入為整體目標、局部意圖、排序影像及分類定義；輸出監督為 JSON 的結果、失敗類別、抓握細類與短原因。原文未列獨立 loss 公式及逐欄 loss 權重，不補猜。
    • Muse-Glimmer-30B 凍結底模，只訓練 LoRA adapter：rank 32、峰值學習率 \(5\times10^{-5}\)、warmup 25 steps、2 epochs、batch size 32、最大 context 65,536。此處學習率是每次更新尺度，不是準確率或收斂保證。
    • 推論 temperature 0，最多 1,024 輸出 tokens；非法 JSON 算錯。

    資料分母不能混用：12,844 是訓練 split，不是所有分析軌跡的總動作數；400 是人工測試子集；恢復分析另用 12,163 個有類別的失敗動作。按 episode 分割也不等於測過跨 benchmark／新機器人泛化。

    三、哪些實驗真正測到了方法？¶

    1. 人工一致性與意圖消融：有用，但不是部署校準¶

    §5／Table 1 在 400 動作上測試：34% 成功、66% 失敗；outcome accuracy 用全部動作，failure-mode accuracy 只用其中 264 失敗動作，另列要求兩者正確的 Overall Accuracy。本文只沿用主表報告，不自行重算未取得的逐筆輸出。

    • GPT-6 Astra：outcome 79.25%、failure mode 80.68%、overall 71.25%。
    • 不提供局部意圖：outcome 25.25%、failure mode 25.00%；作者指出多數被判 unverifiable。這支持「此評估問題需要參照意圖」，不等於測到任務是否選對，也不是一般視覺辨識準確率下降的同義詞。
    • Muse-Glimmer-30B 零樣本到微調：failure mode 32.58% → 74.24%，overall 34.75% → 67.75%。這支持標註配方可轉移到較小 critic；未證明在新分布仍維持相同誤判率。
    • 基線另含 GPT-6.1 Sol／Terra、Claude Fable 5.2／Opus 5.5／Sonnet 5.5、Kimi K3.1 Pro、DeepSeek-V4.1-Flash-1017、GLM-5.3-Flash；這是 critic 比較，不能和 policy 成功率排名互換。

    主表另報 Cohen's \(\kappa\)，即扣除按標籤邊際分布偶然一致的程度；不是準確率，也不是對實機安全的置信保證。本筆記不以單一 accuracy 推估誤放危險動作率，因測試失敗比例及訓練抽樣皆非天然部署分布，且沒有看到按風險校準的閾值／拒答曲線。

    作者在人工初標與 Astra 不一致時再請標註者重看，接受一些複合失敗的另一種合理分類，據此稱一致性超過 90%。不能把重審後容許多解的數字替代原始固定標籤 accuracy。附錄 I 顯示 Astra 把人工失敗誤判 achieved 為 19／264；這減弱「一味偏袒自己」的疑慮，但尚不能排除其他共同盲點。獨立家族模型有接近的 outcome accuracy，也不是所有偏差已消失的證明。

    2. 恢復能力：觀察到後續補救，不代表 critic 使它恢復¶

    跨 12 個 benchmarks：RoboDojo、StationeryBench、Astranomy、UniVTAC、OpenViTac、ContactBench 1.0、LIBERO-MAX、Meta-World+、DexJoCo、RoboWits、RoboTwin 2.0、YAMLab。UniVTAC／OpenViTac 的此處設定為 vision-only，不能據以評斷加入觸覺的上限。

    附錄 C 分析 1,989 個含失敗且有官方評分的 episodes、12,163 失敗動作；其中 RoboDojo 貢獻 9,923，故整體不是等權 benchmark 平均。

    • 38.9% 在後 10 個動作內恢復，57.7% 在 episode 結束前恢復。允許原子目標修復，也允許換路徑繞過；後者 589 個，直接修復 6,435 個。不是所有恢復都等於原計畫被完成。
    • 同一後續成功可同時恢復先前同子目標的多次失敗，且最後一步失敗仍在分母；因此不是獨立救援事件率或平均恢復時間。
    • episode 等權後恢復 60.7%；只取各 episode 第一次失敗則 76.2%。這是不同 estimand，不是三個可互換的「模型恢復率」。
    • Alignment 35.7%、Effect 29.6%，低於 Grasp 63.7%；指向精細對位及接觸效果仍難。恢復與含失敗 episode 的最終成功，跨 benchmark Pearson 相關 0.81；是關聯，不是因果增益。
    • 作者對 24 個失敗的第二次獨立閱讀有 21 次同意是否恢復，仍屬小規模核對；同 episode 重複失敗互相依賴，不應把 action 級誤差棒當成已處理所有聚類不確定性。

    這些主要是事後分析 policy 原本軌跡。附錄 H.1 另有單一 DexJoCo 澆水實例：同初始條件重試，有 critic 回饋者成功、對照失敗；但 feedback 使用 164 simulator calls，對照 12，未形成多任務、固定總預算的隨機試驗。不能把主文 57.7% 說成「加上 critic 後的恢復增益」。

    3. 零樣本表現與控制延遲要分帳¶

    Policy 比較以無任務微調／無示範的 GPT-6 Astra 對照 \(\pi_{0.5}\)（基線 VLA 的模型名稱）及 InternW0-Δ；§4／H.3 報 frontier agent 優勢。本次未逐像素讀 Figures 6、16，不轉錄圖內數字。數值工具動作與基線每觀測一次輸出低階動作的介面不同，亦未由「零樣本」排除未知預訓練資料重疊；不是同延遲／同操作成本的對照。

    附錄 H.2 的 76 個共同 Standard instances，要求與不要求 note 都成功 42 個（55.3%）。只支持這批 aggregate success 沒差，沒有顯示逐任務配對一致、成本相同或所有分布無影響。

    H.4 在 74 個 matched tasks：Astra 決策延遲的彙總中位數 31.9 秒，\(\pi_{0.5}\) 為 0.11 秒。定義是完成最近觀測請求至下一個實際動作提交，包含期間唯讀工具呼叫，再取每次 run 的中位數及跨任務中位數；不是 servo 週期、尾延遲，也不是本文 critic 的推論時間。Table 1 的 400 筆 critic 費用比較同樣不保證控制端到端成本或時效。

    四、核心辨識問題：Choice 稀少，量到的其實是什麼？¶

    作者以 Choice 僅占失敗動作 0.2% 說明 semantic grounding 可靠；附錄 A／J 對定義卻寫得很清楚：

    • 局部 note 說按 3，實際按 7，是 Choice。
    • 全局要求按 3，局部 note 卻說按 7，實際按 7，不是 Choice；局部動作甚至可被評 Achieved。

    因此此數字較直接支持的是「執行通常符合自己宣告的局部物件／順序／類別」，不是「自己宣告的目標符合全局需求」。條件在已判失敗動作上，也不提供所有語意決策的完整分母；codebook 另說保存的 RoboDojo-Precision baseline 未評 M7。把它泛化為全面 semantic understanding，證據跨得太遠。

    本筆記判讀：局部意圖提高評估可識別性，代價是引入一個可錯的參照。需要另一個獨立問題：「此意圖是否值得做、是否允許做、是否仍有效？」這不是否定局部 critic，而是避免讓同一個欄位同時兼任計畫正確性、安全授權及物理驗收。

    可與 Grana 的程序進度帳本對讀：完成度的標籤定義與觀測可用時間都要顯式化；與 LEASH 的逐次授權則只作「履約不等於授權」的問題對照，未證實兩者整合或本文採用其方法。

    五、第一性原理與可重用研究問題¶

    • 最小必要狀態：不能只存結束畫面；至少要有全局目標、原封不動的局部意圖、命令與執行狀態、對齊前後影像，以及接觸語意要求的後續證據。若要回答全局正確，另保留獨立的意圖正確性標籤。
    • 物理限制：夾爪閉合不等於抓住，抓住不等於運送期間仍持有；可見幾何失敗也不等於知道背後力學原因。選幀遮蔽與毫米級接觸會限制判讀，不是換更會說話的 critic 就自動消失。
    • 資料限制：教師標註可蒸餾，但也可能蒸餾盲點；episode split 阻止同 episode 洩漏，沒有測出新域泛化。Partial／Unverifiable 不進此訓練樣本，對其部署校準仍需另測。
    • 時間限制：用後續提起證據判定的抓握結果，最早也要等那個證據出現。可做事後診斷，不能直接冒充動作前安全 gate；觀測／判斷／介入的可逆期限要另記。
    • 方法有效條件：意圖夠具體、影像時序正確、結果可見、分類規則穩定時，局部 critic 能把終局失敗拆為可處理問題；意圖錯置、事件窗口跨過其他動作、狀態不可見或需要快速守界時則可能失效。

    後續只追三個可驗證問題¶

    1. 意圖與執行分開標：設計全局目標正／誤 × 局部履約正／誤的四格測試，包含「錯目標但忠實執行」。固定原始 note，不讓 critic 事後重寫參照；同報局部 accuracy、全局進度及危險誤放。
    2. 去掉後見之明會損失多少？ 固定逐動作時間戳，分報即時可用窗口、加入 lift、加入更晚窗口的識別率與判斷年齡；按 episode／任務聚類估不確定性，再測實際可介入比例。
    3. Critic 真能提高交付嗎？ 在新任務及新機器人上，以相同 simulator calls、牆鐘與 token 預算，隨機比較無回饋、原 note、通用失敗通知及 critic 診斷；同報完整成功、救援成本、誤警與碰撞，而非只比重試中的單一成功案例。
