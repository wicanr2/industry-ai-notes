# Reins：條件動作鏈與旁白新鮮度，要分開驗證

> **問題**：LLM 思考時現場仍在改變；如何減少逐步呼叫成本，又不把整段動作交給過期觀測？
> **方法**：把動作串成帶回傳條件的短鏈，另用 narrator 整理觀測變化；前者縮短決策往返，後者補上 actor 等待期間的事件。
> **判讀**：這是執行介面與時間資訊路徑的改造，不是新控制模型。逐次回傳檢查不是全程安全；持續收影像也不是持續取得新鮮判讀。

## 1. 研究問題：不是「再加一個會看圖的模型」

單次模型決策有兩種成本：推理等待，以及工具執行。每移動一小步就問模型，狀態更新細卻很慢；一次發很多動作，則可能在第一步已失敗後繼續做。另一條獨立問題是：actor 思考時，物體可能已被人換位；下次只看終點影像，無法恢復被遮住物體的身份歷史。

作者提出兩個不同補丁：**guarded chain 讓工具回傳在鏈內決定是否繼續；narrator 讓等待期間的視覺事件不必全部由 actor 事後重看。** 這兩件事不應合併成「閉迴路所以可靠」。它們依賴不同觀測、不同延遲，也需要不同消融。

## 2. 任務與資訊路徑：誰接收什麼、誰能停什麼？

輸入是自然語言任務、頭部／腕部影像、雙臂狀態與歷史；輸出不是關節力矩，而是十八種工具中的呼叫或短鏈。硬體是同桌兩支 6-DoF AirBot Play、平行夾爪及頭部／腕部 RGB-D。

一次迴圈如下（§2、App. A–B）：

1. actor 根據任務和歷史決定看哪裡、量什麼或移動哪一臂。
2. `find` 用 SAM 3 與 RGB-D 把物件登錄為 base-frame 三維位置；`measure` 把像素或輪廓變成三維點。這些登錄與量測可跨呼叫保存，但保存本身不證明物件仍在原位。
3. 原子動作移動、轉向、夾取；`move_until_contact` 依關節電流停，`close_gripper` 由閉合停止位置推斷是否夾住物體。這是代理量測，不是觸覺接觸模型或可靠抓握證明。
4. `do` 在本地串接工具，依每次回傳的條件決定續做、重試或停止。
5. 回傳含量測、**該鏈最後一次執行的影像**、雙臂狀態及上次回傳後完成的 narrator entries；actor 再決策。並非把鏈內每一步影像全送回。

narrator 是同種模型的第二個 instance，以持續對話讀頭部每秒一幀影像，動臂期間另有腕部影像；每次最多送二十幀。它報新增事件、修正或無變化，附時間區間，actor 在工具結果中收到 `what_happened`。它不直接代替低階停止控制器。

### 條件鏈：檢查回傳，而不是證明整條路徑

用原文 §2 的記法，鏈為

$$
P=\big((p_i,\rho_i,u_i,n_i)\big)_{i=1}^{n}.
$$

這裡 $i$ 是步驟索引，$n$ 是步驟總數，$p_i$ 是工具呼叫，$\rho_i$ 是每次結果必須通過的檢查，$u_i$ 是該步重試何時可結束的條件，$n_i$ 是重試上限。每次回傳若不通過檢查就停；若耗盡重試仍未滿足結束條件也停。工具上限為八個 calls、合計十六次 runs。

**真正改動**是把部分控制分支由下一輪 LLM 呼叫移到工具執行器；不是先生成整段無條件軌跡，也不是從 robot demonstrations 學一套新 skill library。但條件由 actor 當場選，若沒檢查關鍵狀態、量測失真或危險發生在工具完成前，通過回傳仍不保證安全。接觸工具約每秒讀電流二十五次；這個局部量測頻率不能借給整個 `do` 鏈當作全程安全採樣率（App. B）。

### 旁白延遲：有錄到，不代表 actor 已知道

原文 Eq. (2) 的核心可寫成

$$
\ell_j \le t-\tau_j < \ell_j+\ell_{j+1},
\qquad t\in[\tau_{j+1},\tau_{j+2}).
$$

$\tau_j$ 是第 $j$ 次送交影像窗口的結束時間，$\ell_j$ 是該次 narrator 呼叫的延遲；$t$ 是已可取得該次回覆、但下次回覆還沒完成的時刻。$t-\tau_j$ 表示**最新已完成報告所涵蓋影像的年齡**，不是相機 frame rate，也不是完整 actor-to-actuator 端到端延遲。

在這種串行窗口排程下，新窗口長度等於上一輪呼叫延遲；慢模型因此同時讓報告變舊、事件被壓進較少輪窗口。公式描述時間覆蓋，不保證旁白語意正確；超過二十幀的窗口也不等於全部影像都送入。不能把「持續觀看」解讀成即時狀態流。

## 3. 資料、訓練與記憶：沒有訓練，不等於沒有任務資訊

這不是微調論文：主實驗使用現成模型，**沒有本研究的 policy 訓練資料集或新學習目標函數**；任務知識經自然語言 prompt 進入，drawer／sweep 另給 grip／pose hints。zero-shot 在此不能改寫為無提示、無工程介面或無感知先驗。

App. A 的持久狀態有物件 ID／位置、量得的輪廓點、task ledger，以及各臂持物／指縫；`done` 在計畫尚有 pending step 時被拒絕。但 ledger 的 evidence 仍由模型更新，不是外部獨立成功裁判。

context 管理也屬方法：actor 文字保留，從上次壓縮起增長三萬 tokens 才批次刪舊影像、留最新帶圖回合；narrator 每六十幀重新開對話並帶首幀與累積敘述，另有六萬 tokens ceiling。用固定幀數而非固定 tokens 避免不同影像 tokenizer 導致重啟頻率失衡。這是特定 provider route 的 cache 工程經驗，不宜直接外推所有 API；批次刪圖亦可能令舊誤判只剩文字而難以復核。

## 4. 真機實驗：把總分、歸因與速度分開

以下是 **作者報告、經本次核 Figure 2 文字**，不是我們的重跑結果。每條件五個 episodes，操作員判成功；沒有獨立盲評或廣泛跨平台驗證。

- **Sol 完整 harness，五任務**：shell game 5/5、drawer 5/5、towel 4/5、shirt 3/5、sweep 5/5。合計 22/25，即摘要的 88%；不是每一任務成功率，也不是三模型平均。
- **模型比較只有部分任務覆蓋**：Astra 在 shell game 4/5、drawer 5/5；Opus 分別 2/5、5/5。不能把五任務 Sol 結果當成三模型都完成五任務。
- **shell game 消融**：Sol 去 narrator 為 2/5，去 harness 為 0/5；完整為 5/5。任務要求在二十至三十秒洗牌後，第一次掀起的杯子就蓋著紅物體。這比允許一直猜到成功嚴格，但樣本很小。
- **時間與成本分母**：完整 Sol shell game 中位時間 1.1 分鐘、平均 API 成本 US$1.40；去 narrator 為 1.4 分鐘／US$0.76，去 harness 為 8.6 分鐘／US$2.66。「八倍時間」是摘要對這個條件的概括，不是五任務普遍加速。API 成本不是硬體、人工、網路與安全驗收的總成本。
- **慢／難任務不能藏掉**：shirt 為 3/5、中位 15.5 分鐘、平均 US$15.51；不能只拿最快 shell game 代表長程部署效率。

Figure 2 共九個條件各五次，與 App. A 所稱四十五個 counted episodes 對得上。正文稱模型 latency 佔總時間 41–78%，支持減少決策往返值得研究，但不等於全部等待都能被安全消掉。

### 消融究竟辨識了什麼？

去 narrator 保留其他 harness 的 shell-game 對照，支持事件歷史對這個遮蔽追蹤任務有用。去整個 harness 則同時改變感知、工具與執行介面；不能只歸因 guarded chain。本文沒有 guard-only／narrator-only／相同感知與工具的完整因子實驗。

Sol 用 Ultrafast tier，另兩模型用 standard tier、高 reasoning effort；作者報 narrator 約 1–6 秒與 3–40 秒差異。故不同模型在洗牌追蹤的差異混有模型能力、服務延遲、窗口數與丟幀策略，**不是純模型理解能力排行榜**。要驗機制，應固定影像流與送達排程，再改模型；另固定模型注入延遲，觀察身份追蹤與第一次選杯。

正文描述去 harness 的五次失敗中四次連杯子都沒提起，一次提錯；因此 0/5 不能全部解讀成「追蹤錯誤」。感知／操作失敗與身份推斷失敗仍應分帳。衣物折疊的失敗沒有逐案例機制剖析，本次不猜是幾何、抓握或推理造成。

## 5. 模擬分支：可執行的 twin，不是已證實的持續學習

App. C 的 `model_scene` **沒有用在 §3 真機 episodes**。單張已校準 RGB 經物件類別／框、SAM mask、類別參數化 Blender builder、單目深度與桌高定尺度，依輪廓擬合位置／尺寸；外觀以逆向渲染擬合，質量與慣量依封閉網格及材料密度設定，再放入 MuJoCo。這不是從一張圖辨識出真實摩擦、剛性和所有接觸參數。

作者設 geometry／settling gate：例如碰撞表面偏差的第九十五百分位不超過三毫米、輪廓距離第九十百分位不超過三像素，另測短時間漂移、初始穿透與布料靜態 strain。百分位門檻不是最壞點界限，像素匹配也不是動力學校準。

五場景十四個可動物件中十一個通過；Table 4 的 IoU／輪廓數字只對通過者報告，不能忽略未通過物件。模擬任務由 scripted mocap hands 執行，而非本文 actor；布料 gate 是靜態檢查。故證據至多支持這些 twins 能載入、部分幾何相符且腳本可演示，不支持「已藉 twin 進行 policy learning，並提升真機成功率」。正文把重用成功鏈與模擬排練列為未來工作。

## 6. 第一性原理：保留哪些狀態，刪掉哪些假設？

**最小必要狀態**至少有物件身份及最後觀測時間、當前幾何／持物量測、待完成任務、尚未確認的事件，以及每個動作條件。身份、位置與時間不能壓成一份沒有有效期的敘述；場景已變時，之前量得的正確三維點也可能錯用。

**為何可能有效**：局部回傳判斷減少 actor 等待；旁白保留終點影像無法恢復的事件序列。兩者只在量測足以支持條件、事件未被漏拍且報告仍及時時有效。

**物理與計算限制**：工具有執行時間，接觸 proxy 有誤差；LLM／narrator 的服務尾延遲不受 prompt 意願支配。若物體變化快於可辨識與送達速度，增加敘述不能重建缺失觀測；若接觸危險先於結果回傳發生，鏈後檢查也救不了先前動作。

**資料與評估限制**：一個平台、小樣本、人判成功、有提示，無法推出部署可靠度或安全保證；sim-ready gate 不能替代真實動力學驗證。

可複用模型是三份帳：**鏈內量測是否足夠 → 事件資訊是否仍新鮮 → 完整任務是否真的改善**。分別量測，再問它們是否有因果交接，而不是把低 API 次數或清楚旁白直接當成工作交付。

## 7. 後續驗證問題

1. 固定模型、感知工具與 prompt，只開關鏈內 guard；在抓空／卡住／物件移位時，是否降低失敗後多餘動作？另測物理停止時間與危險暴露，不只統計呼叫數。
2. 固定錄影片段，分別控制延遲、二十幀上限與摘要更新；身份追蹤正確率、最新有效證據年齡及第一次選杯成功如何改變？把 actor 收到報告的時間也記入端到端帳。
3. twin 通過／未通過物件都納入，對真機接觸與布料動態做獨立校準；模擬排練後是否在同一提示／同一預算、多次開發重複下提升完整任務，而非只展示腳本能跑？
