# Natural-Language to Nav2：政策合法，不等於指令正確或物理安全

> **問題**：作業員說「半小時內別走 A 區」，導航系統缺的不是新路徑演算法，而是可持續、可撤銷且有生效條件的作業政策。
> **方法**：凍結本地 LLM 把語言翻成 JSON；確定性檢查決定是否整筆替換任務，再投影到 Nav2 的 global costmap，不改 NavFn／DWB。
> **判讀**：本文最有用的是把語意、狀態提交與導航效果拆開測；限制也很清楚：通過 validator 仍可能漏掉禁行要求，global costmap 禁行也不是 local controller 的硬安全界線。

## 一、真正缺口：感測不到「為什麼這條路暫時不能走」

LiDAR 能看到障礙，卻不能自行判定裝卸通道保留多久、是否允許火警時例外通行。把指令縮成目的地，會丟掉限制期限與例外；每次都讓 LLM 直接規劃幾何路徑，也不處理限制應否跨任務留存。

本文因此不是訓練新 VLA，也不是用語言模型替換 Nav2。它增加的是 **language → policy → accepted state → costmap** 的管理介面。相對 rule parser，變動在語言理解；相對無政策 Nav2，變動在作業資訊；相對原生 KeepoutFilter，變動主要是政策生命週期與提交管理。三組比較不能合成一句「LLM 導航更好」。

## 二、方法：先明確定義政策，再談執行

### 1. 任務、輸入輸出與資料

輸入為 `/nl_command` 的英文指令、已登記 zone／waypoint 標籤、輸出 schema 及 15 組示範。標籤由既有地圖解析為位置／幾何，不叫模型自行發明區域座標。LLM 在區網工作站執行，不在高頻控制迴圈內。

輸出包含 `plan`（依序目的地）、`via_zones`（必經區）、`exclusions`（含期限／時間區間的禁行）、`weights`（通行偏好成本）、`dynamic_object_rules`（物件類別及避讓半徑）、`conditional_rules`（事件、允許／禁止、優先序）。模型也能明確拒絕。

**沒有模型微調或新 loss**：四個 frozen local models 共用 prompt、15 個 demonstrations；不應把 prompt 內示範稱為梯度訓練資料。語言評估使用團隊設計、AI 協助產生的 150 句測試指令，跨十種意圖、五種措辭層次，每組三變體；示範未逐字出現在測試集，但 prompt／parser／reference／資料出自同一開發流程，不能等同獨立外部測試。

### 2. 接受是整筆交易，不是修好幾個欄位就送出

端點或 JSON 故障先拒絕；validator 再查型別、已登記識別符、數值、跨欄衝突；例如同區同時必經與禁行不成立，非法數字不裁切成合法值。實作 soft cost 範圍為 0–252、物件半徑 0.1–10 m、期限正值且至多 1,440 分鐘。事件只支援固定列舉，並非自由敘述的任意事件推理。

接著拿候選和**當下仍有效的限制／事件**比較，避免格式合法但和既存禁行衝突。可用下式重述 §3.2：

$$
m^+=\begin{cases}u^*,&V(u;r,e)=u^*,\\m,&V(u;r,e)=\bot.\end{cases}
$$

其中 $u$ 是候選政策，$V$ 是含正規化的驗證／情境檢查，$r$ 是另外維護的限制，$e$ 是事件狀態，$u^*$ 是通過後政策，$\bot$ 表示拒絕；$m$、$m^+$ 是提交前後的任務快照。白話是「全部通過才換新任務，拒絕就保留舊任務」。**此原子性只及 bridge 內快照**，不保證下游多個 costmap／機器人同步生效。

普通任務省略的限制不繼承；永久與排程限制另存。進行中指令進 FIFO queue，等到提交前重查情境，並在取消舊 goal 前再次確認。拒絕不新增 goal 或投影，但既有 timer／事件仍繼續處理。重送相同靜態內容不代表計數器與導航請求都無副作用。

### 3. 投影與導航迴圈：LLM 提案，Nav2 算路

接受後經 `/follow_waypoints` 發 goal；三個 adapter 在 **global costmap** 加入禁行、偏好成本及人員周圍區域。keepout／物件區域用 254；soft cost 用 0–252，不能清掉感測障礙。YOLOv8 加 RGB-D 提供人的 map-frame 位置，半徑只是政策區域大小，不是已達成的實際安全間距。

對已知格點，可重述 §3.3：

$$C_{\mathrm{pre}}(x)=\max\{C_{\mathrm{sensor}}(x),C_{\mathrm{keepout}}(x),C_{\mathrm{soft}}(x),C_{\mathrm{object}}(x)\}.$$

$x$ 是地圖格點，四個 $C$ 分別是感測、禁行、偏好及物件層成本，$C_{\mathrm{pre}}$ 是 inflation 前的合成成本；取最大值使低偏好成本無法覆蓋高障礙成本。**只適用已知格點**；unknown 的更新另循 Nav2 規則，inflation 也可能蓋過較小 soft cost。本文沒有把政策送進 local costmap，因此不能聲稱 local-controller 軌跡被政策硬約束。

時間端點轉為 ROS clock，ROS timer 管期限；S2 記載每秒檢查 expiry。事件許可只移除適用的政策禁行，保留感測障礙與不可覆寫限制。兩機分享的是 policy-derived updates，各自定位、感測、規劃、控制；不是 fleet collision／deadlock 解法。

## 三、實驗分三本帳：理解、遏止、路徑

### 1. 語言轉換不是只看 JSON 是否有效（§4、S1、S7）

150 指令逐一比完整正規化政策，目的地次序、禁行、期限、成本、半徑與事件都須正確，也不能多加可執行項目。四模型以 temperature 0、top_p 0、seed 42，各句五次固定設定呼叫得到同樣彙總；**不是 750 個獨立句子**。

- Rule parser：正確接受 44、錯誤接受 101。
- Llama 3.1-8B：107、20；Qwen2.5-7B：122、10。
- Qwen3-8B：141、7；Qwen3.5-9B：142、3。
- Qwen3.5 的剩餘結果是四次 interpreter rejection、一次 validator rejection（表 S3），不是把所有不正確結果都當成被安全擋下。

最強模型也有漏前置停靠點、漏 C 區禁行、多加避人限制（表 S12）。四 LLM 合計的 40 個錯誤接受 model–command cases 中，六個漏禁行或人員避讓；錯誤類型可重疊，不能將表 S11 各類直接相加當案例數。這是內容風險分類，**不是實測碰撞率或違規率**。

Qwen3.5 的正確接受名目 95% Wilson 區間為 [89.8%, 97.3%]，但共享意圖、改寫相關性與開發偏差不在區間模型內；它不能當現場可靠度保證。候選生成平均延遲為 1.694–3.011 秒，僅量 policy generation，不是任務端到端時間或控制迴圈延遲。

### 2. 故障拒絕有效，但看不見被翻譯漏掉的限制

37 項注入故障（八項 endpoint／JSON，29 項 validator faults）全拒絕且保留舊任務；S2 的 102 項 Python tests 及八項 node-level checks 用 instrumented substitutes，證明的是軟體請求／狀態轉移，不是物理停車安全。100 句矛盾指令另測辨識與邊界阻擋；若 LLM 先漏掉矛盾一邊，下游看起來便沒有衝突。

**版本口徑須留意**：S6.2 承認語言評估 snapshot 的 soft-cost 上限為 253，實作測試版為 252，而且後者多測 active restrictions。作者稱保存輸出不含 253，僅改 archived validator 的上限不改這批決策；這不代表兩版整體語意／所有動態情境等價。

### 3. 導航收益先拿正確政策測，沒有穿過完整語言錯誤鏈（§5–6、S3）

模擬為固定倉庫，真機為 TurtleBot3 Waffle 迷宮；Tasks 1–3 每條件十次完整 run，固定起點、地圖、終點與障礙條件，比 baseline NavFn／DWB／sensor layers 與加政策成本的版本。指標為 mission-start 到 completion 的時間與里程。

例如真機 Task 1（提前知道封路），平均時間由 62.179 秒降為 40.390 秒；95% Welch 差值區間 [20.596, 22.982] 秒。其他任務測偏好路段、人的區域。Task 4 是同一 policy-enabled stack 的 permission off/on，不是與無政策 baseline 的同一比較；真機時間為 46.280 與 26.640 秒。

這些比較採**正確任務政策**，baseline 沒有新增作業情報；支持「更早拿到有效資訊能少繞路」，不獨立證明 LLM 比 GUI／規則表輸入的相同政策更有效，也沒有給自然語言至完成／遵規的端到端率。Welch 區間描述固定測試條件下平均差；S3 明說沒有多重比較校正，極小 run-to-run SD 也不是跨場域穩健性。

最重要的反證控制在 §6.1：繞過 LLM／validator／bridge，給原生 KeepoutFilter 與 custom adapter 同樣禁行。各五次重啟 run 都完成，時間／路程相近；45,384 個抽樣格點比較無差異。此結果只及一個模擬案例與指定區域、pre-motion 更新，不證明所有動態情境等價；計時從**首次移動**開始，也不能直接混進前述 mission-start 表。

**消融界線**：本文有模型替換、故障測試、事件 on/off 及原生 keepout 控制；沒有完整拆解 validator／queue／timers／人工確認各自對自然語言端到端遵規的增益。兩機 demo 是共用區域投影，不是多機避碰壓力測試。

## 四、第一性原理：最少要保存什麼，才知道下一步是否合法？

本筆記整理的最小狀態不是整段聊天，而是：登記地圖語意、任務快照、跨任務限制與期限、事件狀態、候選政策和有效時間。物理執行還需要當前定位、感測與更新是否送達；後者不能從 bridge 的 commit 推定成立。

方法可能有效，是因為將開放語言壓成有限契約，讓可判定的衝突在執行前處理，同時沿用成熟規劃器。失效條件也由此直接推出：

1. **資料限制**：開發者自己設計的英文改寫不代表現場中文、口語更正或多人互斥授權；schema 外語意可能被靜默遺失。
2. **資訊限制**：validator 只能檢查收到的政策；沒被翻出的必要禁行不能靠型別檢查找回。
3. **時間／分散式限制**：快照提交、timer 到期、ROS topic 傳送與各機 costmap 生效不是同一時刻；一秒 expiry 檢查也不等於精確到秒內強制切換。
4. **物理限制**：global 禁行與 person radius 沒有自動變成 local trajectory constraint；定位、深度、偵測、煞停能力仍限制實際間距。
5. **授權限制**：誰能解除永久禁行或宣布事件例外，本文提出未來應補確認／授權，不能寫成已實作並驗證。

## 五、接續舊筆記：把「合法」分成三層

[AW-0](../2026-10-26/01-aw0-程式條件與執行收益要分帳.md)提醒程式無例外不等於物理完成；[BT-Agent](../2026-10-13/01-bt-agent-固定技能與反應式護欄.md)提醒強制中斷須在模型之外。本文再補上：**schema／情境合法、符合原始指令、物理執行守界**是三種不同證據。它不是安全認證，也不因有 validator 就補齊 BT-Agent 的 guard。

可複用研究模型是「提案正確性 → 狀態提交一致性 → 投影送達 → 物理遵規」四段鏈；每段各設分母與失敗紀錄。這是本筆記整理，不是作者已完成的端到端證明。

### 後續驗證問題

2. 同一正確政策以 GUI、rule parser、LLM 輸入，在相同 Nav2 下分開量轉換延遲、確認成本與遵規；導航收益究竟來自資訊還是語言介面？
3. 注入 topic 遺失／延遲、時鐘差、兩機不同步及 local-controller 偏離，量「接受到全機生效」時間與真實禁區侵入／最近間距；哪些限制需要獨立 local guard，而不能只靠 global costmap？
