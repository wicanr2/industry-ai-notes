## 為什麼選這篇

這篇研究的是 LLM / VLM 進入實體機器人後，一種不同於傳統網路入侵或對抗貼片的攻擊面：攻擊者只要把人類可讀文字放進機器人視野，就可能把場景內容變成間接 prompt injection。它把軟體代理中常見的「不可信資料與指令混在一起」問題，轉成真實世界的安全問題。

它與一般 VLA 效能論文有獨立價值：不是追求更高成功率，而是詢問感知到的文字有沒有權限改寫操作者的命令。摘要給出跨三個 VLM、5,670 次試驗與三類簡單防禦的結果，但本筆記沒有讀取實驗章節，因此不把這些數字直接外推到動態、閉迴路或安全關鍵機器人。

## 一句話理解

VLM 控制器若無法區分「場景中看見的文字」與「有權限下達的命令」，一張紙就可能成為實體世界的 prompt injection 通道。

## Summary / Abstract 說了什麼

作者把 physical prompt injection 定義為：在機器人的視野內放置對抗文字，文字經由視覺感知進入 VLM 的推理脈絡，進而重新導向動作規劃，而不需要接觸軟體或網路。

研究建立四類攻擊分類：間接標示（indirect signage）、任務重定義（task redefinition）、權威冒充（authority impersonation）與衝突注入（conflict injection）。基準包含 20 個攻擊提示、三種實體場景布局，以及三種在目的地明確度與規則顯式程度上不同的操作命令。

摘要自稱，在 5,670 次試驗中，GPT-4o、Gemini 2.5 Flash、Qwen3-VL-32B 的攻擊成功率分別為 27.0%、29.4%、5.0%；權威冒充與否定型攻擊可跨三個模型轉移。作者也稱成功入侵時，模型的 reasoning trace 幾乎總是有察覺攻擊文字（99.9% acknowledgment rate），但不同模型的防禦機制不同。

三種簡單緩解方式是防禦提示、兩階段驗證與先遮蔽影像文字。摘要宣稱它們可大幅降低攻擊，但也指出文字遮蔽可能傷害本來就需要讀取場景標籤的任務。

## Introduction 的問題設定

Introduction 先建立 VLM 在機器人中的角色：它們可做開放詞彙辨識、語意 grounding、任務分解與高階規劃，因此讓機器人從任務專用策略走向語言條件化的通用系統。

接著作者區分三層攻擊面：傳統 ROS 網路與 middleware 攻擊、對視覺分類器的物理對抗圖樣，以及本文關注的「物理傳遞、語言機制」攻擊。後者使用正常可讀文字，不必製造對人眼無意義的微擾；風險來自 VLM 把場景資料當成可以覆寫任務的指令。

作者認為，既有 indirect prompt injection、影像文字攻擊與 embodied-agent jailbreak 已揭露部分問題，但仍缺少對真實工作空間中、人類可讀標示如何影響 VLM 機器人規劃的系統研究。因此本文用蔬果分類與彩色籃子的受控任務，比較不同攻擊類型、不同原始命令清晰度與不同模型。

值得注意的是，Introduction 描述的是使用真實工作空間照片、要求模型輸出結構化動作計畫的 static-image protocol。這與機器人實際執行閉迴路運動仍有距離，因此「VLM 規劃被改寫」與「實體機器人確實完成危險動作」不能直接視為同一證據。

## 研究的第一性問題

- **基本問題**：多模態模型看見文字時，如何判斷那是被觀察的資料、任務所需標籤，還是有權限改寫行為的指令？
- **約束**：機器人有時必須讀場景文字；全部遮蔽會失去能力；語言權限與來源在像素中通常沒有可靠標記。
- **既有方法卡點**：VLM 的通用 instruction-following 能力同時也是攻擊入口；只靠「遵守最初指令」的提示可能依模型與措辭而變。
- **作者試圖移動的邊界**：把 prompt injection 從瀏覽器、文件與 agent tool output，擴展成可量測的實體場景威脅模型與防禦比較。

## 可能的貢獻與限制（只基於 summary + introduction）

### 論文自稱

- 提出 VLM 控制機器人的四類 physical prompt injection taxonomy 與 20 個攻擊提示基準。
- 以三種命令形式測量原始指令的明確程度如何影響脆弱性。
- 比較三個 frontier VLM 的攻擊成功率、類別差異與推理反應。
- 評估防禦提示、兩階段驗證與文字遮蔽三種可部署緩解方式。

### 我的保守判讀

- 安全問題設定很重要，尤其揭示「感知內容沒有天然指令權限」；但 static-image 的結構化規劃輸出，不等同完整機器人系統已被實體劫持。
- 受控分類任務有助於比較，卻可能低估或高估複雜場景中的風險；攻擊成功率不能直接搬到工廠、家庭或人形機器人。
- reasoning trace 的 acknowledgment 不必然等於模型內部「有意識」辨識攻擊；它只是可觀察文字輸出的行為指標。
- 文字遮蔽達到的防禦效果可能來自直接移除功能。真正困難的是保留 OCR / 標籤理解，同時限制不可信文字的控制權限。
- 尚需檢查攻擊成功定義、重試方式、模型版本、溫度、置信區間，以及防禦是否對未見攻擊仍有效。

## 可放進資料庫的筆記

1. **像素不是可信命令通道**：視野中的文字預設應是資料，而不是具備控制權限的指令。
2. **Physical AI 需要資訊來源標記**：系統要保留 operator command、環境標籤、工具回傳與模型推測的 provenance。
3. **能力與攻擊面共用同一介面**：機器人越會讀字、理解權威語氣，就越需要權限隔離。
4. **否定與權威措辭是跨模型壓力測試**：安全測試不應只做隨機文字，而要測「安全通知」「系統更新」「忽略前令」等社會語意。
5. **防禦不能只看 attack success rate**：還要量測正常任務能力損失，尤其是需要閱讀標籤的工作。
6. **規劃層被攻擊不等於致動器必須執行**：下游 safety monitor、動作白名單與物理限制可形成第二道邊界。
7. **靜態 VLM benchmark 是風險篩檢，不是完整安全證明**：閉迴路、視角變化、OCR 穩定性與實際致動都會改變結果。
8. **「模型有看到」與「模型服從」要分開測量**：感知、解讀、權限判斷與動作批准是不同階段。

## 後續想追的問題

1. 攻擊成功率的統計單位、置信區間與重複採樣方式是什麼？
2. 三種防禦對未見措辭、不同語言、手寫字與遮擋文字是否仍有效？
3. 若任務本身要求讀取貨架、門牌或安全標示，系統如何分辨資訊與命令？
4. 加入獨立的動作安全驗證器後，規劃層攻擊有多少會真正到達致動器？
5. 動態影片、多視角與閉迴路互動會放大還是減弱攻擊？
