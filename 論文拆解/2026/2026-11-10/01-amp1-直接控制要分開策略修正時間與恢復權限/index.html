    AMP1：直接控制，要分開策略修正、時間與恢復權限¶

    問題：通用模型若不只選技能，而能看圖、寫程式、直接指定末端軌跡，是否更能處理未預見的操作？ 方法：AMP1 把持續存在的 Python interpreter、可編輯場景模型與定時路徑點接給模型；策略在每輪觀察後重寫，並非每個控制 tick 都重新推理。 判讀：成功率和介面消融值得重視，但模擬暫停推理、真機不計推理時間、恢復權限不同，限制了「可靠」能被外推到哪裡。

    1. 缺口不是「能不能產生動作」，而是誰能改變策略¶

    作者區分四條路：從機器人示範學端到端政策的 VLA／WAM；由模型調用既定抓放技能的 orchestration；部署前生成控制程式的 offline program synthesis；以及執行期間持續讓通用模型決策的 agentic manipulation policy（AMP）。程式本身能有 feedback，不表示生成它的模型仍在環中。

    AMP1 的核心改動是讓通用模型保有策略與幾何決策權：選擇看哪張圖、修場景表示、決定抓哪裡、先推再抓，以及失敗後另寫一條路徑。它不是直接預測馬達扭矩，也不是移除低階控制器。這個區別比「不用技能」更精確：基本 harness 不內建抓取／放置策略，但仍提供感知、運動學、插值、路徑檢查與硬體控制基礎。

    2. 方法：一條可回看、可修補的觀察—程式—軌跡迴圈¶

    任務、輸入與輸出¶

    任務是依自然語言在有限步數內完成操作。輸入由 SDK 提供指令、RGB、可用時的深度與相機標定、關節與夾爪狀態、剩餘步數／時間；模型主動顯示圖片後，圖片才進模型 context，不是每個 tick 自動連續送影像。Python kernel 保留變數、歷史影像與函式，較早圖片可被檔案指標替代，再需要時重載。

    模型輸出 Python 程式，透過 SDK 產生定時末端路徑點：

    \[ w_i=(T_i,t_i,g_i),\qquad T_i=(p_i,R_i). \]

    這是原文 §4A.3 的介面：第 \(i\) 個點的 \(T_i\) 是機器人基座座標下的工具中心點（TCP）位姿，\(p_i\) 是三維位置、\(R_i\) 是三維旋轉；\(t_i\) 是希望抵達的時間，\(g_i\in\{0,1\}\) 是夾爪開／關。它約束「在哪裡、何時、夾爪怎樣」，不直接指定接觸力，也不保證物體不滑落。雙臂各有一串路徑點。

    感知與狀態維護¶

    harness 將融合點雲做 voxel clustering，使用幾何鄰近與顏色分開相接物件；把可見頂面向下延伸成封閉 mesh，建立障礙區域。跨更新以位置、大小、顏色配對維持 ID。這是近似幾何：遮擋可能被填錯、接觸物件可能合併、同一物件也可能切開。

    模型能對照相機圖，從像素擴出物件、定義 box／點集合、刪掉錯誤物件，修正持續場景模型。prompt 要求動作後更新場景並看圖。因此不是相信一次 segmentation 後一路開環；但能編輯也帶來責任：模型若刪除真障礙，不會因 scene graph 更乾淨就更安全。

    運動與控制邊界¶

    harness 在路徑點間分別插值位置和旋轉，採 quintic time scaling；再以 damped least-squares inverse kinematics 從前一步關節狀態求下一步。執行前檢查位置／旋轉誤差與關節速度，超限會回傳原因和受影響步驟供模型改寫；接近關節極限／奇異點有警告。

    基本版不是強制全程防碰撞投影：可達與速度檢查是必要門檻，但沿軌跡取樣檢查碰撞由模型另行呼叫；碰撞模型用球近似機械臂／夾爪，障礙來自感知物件，也能排除預計接觸的目標。因此「preview 通過」與「沒有危險接觸」不可畫等號。軌跡一旦執行，模型不能中途重新考慮；硬體 collision reflex 才是另一層停止機制。

    讀到的 S3 香蕉範例展示完整鏈：先查物件／相機 → 以點雲估抓取位置與方向 → preview → 額外檢查出桌面碰撞而抬高抓點 → 執行 → 看圖／夾爪狀態發現滑動 → 重新量測 bowl 位置與搬運淨空 → 放下，由 benchmark verifier 判定成功。這支持「可觀測、可修程式」的機制說明，不是每回合都能正確自診斷的證明。

    資料與學習目標：零樣本、練習和持續學習別混在一起¶

    • 零樣本 AMP1：每 episode 使用全新 sandbox kernel，沒有本任務示範、事前 rollout 或權重更新；但通用模型與立體深度模型原已預訓練，不能說完全沒用學習資料。本文沒有訓練新的端到端控制 loss。
    • Few-shot AMP1+：在 RoboDojo 每輪並行 4 個不同 layout，最多 48 個練習 episodes／12 輪。反思 agent 看到歷次 binary rewards、messages／code／outputs／images 與舊記憶，更新一個不限格式的資料夾，通常含 Markdown 規則與 Python 技能。評估 agent 只拿凍結後的記憶，不看反思者全部 transcript。
    • Continual AMP1+：42 個任務以一個隨機順序各嘗試一次，得到成敗後改寫跨任務記憶；要求保留可複用的 embodiment 經驗。權重固定，改的是外部記憶與程式，不是用梯度學新 policy。

    以本筆記簡寫，其改動是 \(M_{k+1}=\operatorname{Reflect}(M_k,\mathcal{T}_{\leq k},r_{\leq k})\)：\(M_k\) 是第 \(k\) 輪前的外部記憶，\(\mathcal{T}_{\leq k}\) 是截至該輪的執行紀錄，\(r_{\leq k}\) 是二元成敗。這是資訊流摘要，不是作者提供的最佳化方程或收斂保證；記憶可能過度擬合 verifier，也可能固化錯誤策略。

    3. 實驗到底測了什麼¶

    模擬主榜：成功率很高，但不是同牆鐘吞吐¶

    • RoboLab-120：120 任務，每種 default／vague／specific 指令各 10 episodes，合計 3,600；同任務初始場景固定，變化來自政策與模擬非確定性。default 的 AMP1 + Gemini 4 Argon 為 85.6%，Opus 5.5 為 82.8%；圖中 BiMind v0.5 為 49.2%、FLUX 3 Action 為 42.9%，Lakeside 51.0% 是另一路 learned policy，不能把 49.2% 說成所有 learned policies 的最高值。多數基線是公開榜單值，不是本研究在完全相同硬體與時間配置重跑所有模型。
    • CaP-Gym：LIBERO-PRO 的 60 個任務／擾動條件各 50 次，共 3,000；robosuite 7 任務各 100 次，共 700；BEHAVIOR-1K 只含兩個任務、各 25 次，共 50。Gemini 版依序 95.2%、100.0%、96.0%，不能寫成整個 BEHAVIOR-1K 都達 96%。LIBERO-PRO 的 few-shot HarnessPAI 為 96.5%，亦不能說 AMP1 贏過所有基線。
    • 時間與感測口徑：RoboLab／CaP-Gym 在模型推理時暫停模擬，步數／模擬時間限制只算動作；深度無噪、標定精確。高分可支持受測設定下的操作能力，不直接支持在外界不停移動、滑動或有人走入時的可靠性。

    真機：104/108 要與恢復消融、時間分母一起看¶

    12 個任務、3 套同型 Franka Research 3／Robotiq 平台，每平台每任務 3 次，共每方法 108 次。作者用 scene restoration 保持起始物件一致；桌面背景、標定、線材、磨耗不同。這不是跨三種機器人形態的真機驗證；雙臂及移動操作的廣度主要來自模擬。

    Table 1：Opus 版 AMP1 開啟 recovery from error（RfE）成功 104/108（96.3%）；FLUX 49/108（45.4%），π0.5 30/108（27.8%）。但 baseline 遇控制器錯誤就結束，AMP1 可以讀取錯誤、請求恢復再續行。Table S1 拿掉兩個恢復函式後，AMP1 為 94/108（87.0%）。這仍值得研究，卻表示主表差距是策略與系統權限的組合，不能全歸因於模型推理。

    作者設定共同 5 分鐘「執行」預算，不含推理。Table 1 只對成功 trials 報 time-to-success；AMP1 平均執行 69 秒、reasoning 欄 211 秒、總計 280 秒，baseline 分別為 62／44 秒。補充 S1 解釋 reasoning 欄還包含自行產生程式的執行、相機擷取與動作後 3D 感知，不是純 API 思考時間。不能以這些不同成功子集的均值直接計算每合格件成本，也不能將「5 分鐘內完成」解讀為牆鐘保證；個別 AMP1 成功任務總時間為 601 秒。

    失敗仍有倒立碗滾落桌面、倒料掉出目標盤；大量 struggle 涉及桌面、箱壁與自碰撞，簡化幾何未建模線材／相機支架。硬體停止後能恢復，證明的是恢復路徑，不證明前次接觸可接受，更不代表模型獲准解除任意安全停止。

    記憶：84.1% 包含驗證集選模，不是單次練習的自然結果¶

    RoboDojo 有 42 個雙臂任務，依五類先各自平均、再平均五類；不是把全部 episodes 混成單一分母。seed 0 蒐集經驗，每任務獨立練習 五次，按 seed 1 成功率選最佳 run，最後 seed 2 測試。few-shot 26.4% → 84.1% 要連這個選擇預算一起報，不能描述成只用 48 episodes 就必然得到 84.1%。Continual 在一個任務排列下到 57.6%，尚非多排列的穩健遺忘結論。此處 95% CI 是按類別內重抽任務的 percentile bootstrap，不是外界任務分布上的安全界。

    4. 消融支持哪個機制，還欠什麼對照¶

    1. 固定 harness 換模型與推理量：Opus 5.5 增加 reasoning 從 68.2% 到 82.8%，支持能力與測試時計算有關；尚不能從這一表識別具體內部空間推理機制，也未做等 token／等延遲／等成本配對。
    2. basic 對 assistive：Opus basic 82.8%，加抓放例程 75.3%；弱模型 Qwen3.6-35B-A3B 則 14.2% 到 31.8%。作者解釋為內部重試隱藏失敗細節，強模型失去及時修正機會。本筆記判讀：同模型結果支持這一套介面的粒度值得重做，不支持「所有預製技能都不如直接控制」。還缺回傳完整失敗 trace、可中斷、同樣控制權的技能對照。
    3. 感知消融：Opus 全感測 82.8%，無深度但有標定 81.1%，只有 RGB 75.8%；平均 model calls 從 34.8 到 46.3／53.5。這是以額外觀察／計算補幾何，不是感測資訊毫無價值。Haiku 只剩 RGB 時為 10.7%，也不能將強模型結果泛化到任意 LLM。
    4. 影像對文字：Opus RGB 75.8%，改由另一個同模型產生相機文字描述為 36.8%。較適當的對照是這對數字，不把所有落差都混成與全感測 82.8% 的比較。結果反對此文字通道的壓縮方式，不證明任意結構化幾何語言皆無效。

    5. 第一性原理：可修正的控制權，需要足夠觀察，也需要剩餘時間¶

    最小必要狀態不只是物件名稱：至少要有可用的幾何／座標、機器人與夾爪狀態、動作承諾區間、目標及已知失敗，再加剩餘時間。AMP1 的特色是允許模型重新取得這些狀態、修改程式，而不是靠固定技能返回一個成功／失敗 bit。

    但「事後看得懂」仍取決於世界變化得多快。若滑落在路徑執行中就發生，下一輪重新規劃再聰明也可能太晚。可複用判準應是：介面能否提供錯誤原因 → 模型能否提出有效修正 → 修正能否在不可逆後果前生效；成功率只涵蓋這串鏈在受測環境裡的總結果。

    與 VLALagBench 的觀測年齡／停頓、ARP 的快視覺／慢語意對讀：AMP1 現在優先交還策略修正權，沒有解決動作中重新推理的時間尺度。這是互補研究問題，不是已整合的系統。再與 VLA-Tug 的警報與介入分帳區分：警報、清錯誤續行、損害可接受是三個不同端點。

    後續驗證問題¶

    1. 固定每回合牆鐘期限與成本，外界不停模擬，分報完整成功、尾延遲、碰撞與落物；basic 的優勢在什麼動態速度下消失？
    2. 為所有方法提供相同且受獨立安全政策限制的恢復權限，再比較碰撞次數、停止後續行成功、損壞與人工介入，模型優勢還剩多少？
    3. 保留技能但打開中間觀測、完整錯誤訊息與取消介面，做介面因子實驗；強模型退步究竟來自技能本身、隱藏狀態，還是無法及時收回控制？

    可修正結論：本文把「用通用模型做操作」從技能選擇推到可編輯狀態與軌跡的在線程式迴圈，提供強而有界的證據；下一步不是用榜單宣布 VLA 無用，而是把策略修正權、物理時間與恢復授權放到同一套公平評測裡。
