    VeriVLA：驗證算力必須買到更好的動作¶

    同一個 VLA 策略能抽出不同動作，不代表多抽幾次就會進步；還需要知道何時值得抽、如何選，以及等待是否讓觀測失效。 VeriVLA 用雙軸動作訊號啟動額外採樣，再以潛在世界模型預測任務進度增量，挑選候選動作。 本筆記的判斷：消融支持「預測未來狀態」有助選擇，但觸發訊號仍是代理指標；真機 65.5% 是含部分完成的分數，不是完整成功率。

    一、問題不是會不會生成，而是何時值得挑選¶

    Flow-based VLA（以流匹配生成連續動作的視覺—語言—動作模型）會由不同隨機種子產生不同 action chunk，也就是連續一小段控制動作。若每輪只執行第一個樣本，策略其實放棄了候選之間的品質差異。

    但「多採樣」本身不是答案。第一，容易的移動階段不值得每輪都做昂貴驗證；第二，VLM 直接看動作判分未必理解執行後果；第三，先生成未來像素再評分，會多一個生成品質與延遲瓶頸。

    作者的真正改動是把兩個決策拆開：以動作的變化／分歧決定是否花算力，以 action-conditioned latent dynamics 判斷花完算力要選誰。基礎策略部署時不更新，但驗證器需要事先訓練；「training-free」只指觸發規則，不能形容整個系統。

    二、任務、輸入輸出與實際控制迴圈¶

    每個決策時刻，策略接收相機觀測、語言指令與機器人本體狀態；改變高斯噪聲種子，產生多個候選動作段。驗證器另有任務專屬、可學習的 query token；它不是完全不需適配的開放詞彙通用裁判。

    用較不易混淆的記號重述作者的選擇目標：

    \[ \Delta p_t=p_{t+H}-p_t,\qquad i^*=\arg\max_{i\in\{1,\ldots,K\}}\sum_{j=1}^{M}\widehat{\Delta p}_{i,j}. \]

    這裡 \(t\) 是決策時間索引，\(H\) 是一段包含的動作步數，\(p_t\) 是任務進度；\(K\) 是候選總數，\(M\) 是一段再切出的子段數，\(\widehat{\Delta p}_{i,j}\) 是候選 \(i\) 第 \(j\) 子段的預測進度增量，\(i^*\) 是被選出的候選。白話說：不是選「看起來離終點近」的動作，而是選「預測這次能多推進多少」的動作。進度定義來自標註模型與任務，並非物理真值，也不是安全風險上界。

    實際流程（§3、§4.1、附錄 B／D）：

    1. 同一觀測先抽 2 段動作；依各段平均動作幅度做正規化，降低只因移動很快就觸發的偏誤。
    2. 計算段內相鄰動作的平均平方變化，以及不同樣本在相同時間位置的分歧。
    3. 用新環境少量基礎策略 rollout 建立兩種訊號的經驗參考分布；將數值換成各自百分位。
    4. 任一百分位超過門檻就啟動驗證；不啟動時執行第一個樣本，不是兩者平均。
    5. 啟動時再抽 8 段，合成 10 個候選；每段分成 5 個子段，預測各子段未來 latent 與進度增量；執行累積增量最高的整段，下一輪取得新觀測再決策。

    觸發器的 OR 規則為：

    \[ \tau(s_t)=\max\{\tau_{\mathrm{temp}}(s_t),\tau_{\mathrm{cross}}(s_t)\}>\tau_0. \]

    \(s_t\) 在此沿用作者表示狀態的記法；\(\tau_{\mathrm{temp}}\)、\(\tau_{\mathrm{cross}}\) 分別是時間變化與跨樣本分歧的經驗百分位，\(\tau_0\) 是啟動門檻。這些百分位不是失敗機率或校準過的信心值；環境／策略改變可能需要重建參考分布。少量校準 rollout 的可行性是作者的經驗敘述，文中沒有給通用樣本複雜度保證。

    三、世界模型到底學什麼，如何避免只背任務¶

    架構與因果順序¶

    驗證器採 JEPA（Joint-Embedding Predictive Architecture，聯合嵌入預測架構）式潛在世界模型：凍結的預訓練視覺編碼器把影像壓成 latent，動作條件式 autoregressive predictor 預測其演化；不同機器人有對應的 state／action encoder，將原始狀態與動作投影到 predictor 的嵌入空間。

    每個子段先預測下一個 visual latent，再估對應進度。任務 query 提供「開櫃」與「關櫃」等同一物理轉移的不同任務意義。Attention mask 不讓 latent dynamics 預測讀取任務 query，意在減少靠任務語義走捷徑，而不是學環境動態。

    這項設計意圖合理，但本文沒有提供單獨移除該 mask 的閉迴路消融；因此不能把「成功隔離捷徑」當成已被獨立識別的效果。

    資料、標籤與目標¶

    真機每個任務先收 50 段示範微調基礎策略，再收 50 段策略 rollout，以 Robometer 自動標註絕對進度，再相減得到子段進度標籤。環境內多任務共用驗證器；LIBERO 每個基礎策略各有自己的驗證器權重，不是同一份驗證器直接跨策略零樣本通用。

    Predictor 另有 DROID 23k 軌跡預訓練；凍結 visual encoder 來自 V-JEPA 2。訓練目標可寫成：

    \[ \mathcal L=\mathcal L_{\mathrm{prog}}+\lambda_{\mathrm{vis}}\sum_{j=1}^{M}\|\hat z_j-z_j\|_1. \]

    \(\mathcal L\) 是總損失；\(\mathcal L_{\mathrm{prog}}\) 結合進度的 Huber 回歸與同任務樣本對的排序損失；\(\hat z_j\)／\(z_j\) 為第 \(j\) 個子段的預測／目標 visual latent；\(\|\cdot\|_1\) 表示逐元素絕對誤差加總，\(\lambda_{\mathrm{vis}}\) 平衡視覺預測監督。上式省略原文時間下標，保留其作用而非改定義。排序 margin 依目標進度差設定；空的可排序樣本對集合不產生排序損失。

    附錄 B 列出實體適配的 batch size 32、AdamW、learning rate \(5\times10^{-4}\)、visual／rank loss 權重皆為 1，以及單張 H800。訓練同時使用 teacher forcing（餵真實歷史 latent）與 self-forcing（餵自己預測的歷史 latent），推論只用預測歷史滾動。本文列出的設定未交代兩者混合比例、完整訓練時長，也未在該表列出所有排序超參數，不能自行補齊。

    白話上，visual loss 要求判分前真的預測狀態轉移；排序 loss 則把訓練資源集中在「哪個動作較值得執行」，而非只追絕對分數漂亮。是否學到真實接觸機制，仍受編碼器可見資訊與自動進度標籤品質限制。

    四、實驗能支持哪些判斷¶

    以下均是作者報告的結果，未經本筆記重現。來源為 §4、Tables 1–5 與附錄 C／D。

    真機：進度加分，不等於整次任務成功¶

    • 平台／任務：AgileX PiperX 雙臂、一部前視 D455 與兩部手腕 D435；插筆、移液、放蘋果。每方法每任務 50 trials，部署策略與驗證器共用一張 RTX 4090。
    • 指標：validation rank／Huber loss，以及閉迴路 completion score。抓筆／插入各 0.5 分；移液四階段各 0.25 分；抓蘋果／放入各 0.5 分，若放置須多次嘗試，放置階段只得 0.25 分。故不能由平均分反推出完整成功率。
    • 對照：基礎 \(\pi_{0.5}\) 單次採樣 50.8%；採 RoboMonkey 路線、改以進度增量訓練的 VLM verifier 56.0%；採 GPC-RANK 路線的像素世界模型 verifier 52.8%；VeriVLA 65.5%。
    • 本筆記判讀：支持這套完整系統在三任務上比所實作基線更好；不代表原方法所有公開實作都輸，也不能把不同架構的額外資料／預訓練成本視為相同。未見多隨機種子置信區間；50 trials 的穩定性仍待驗。

    模擬：分清 always-on 與 adaptive trigger¶

    • RoboTwin 2.0：基礎為 Hy-Embodied-0.5-VLA；選五個較低基線成功率的精細任務：掛杯、轉開關、蓋章、放滑鼠、掃描物件。Table 2 是 always-on verification：Clean 66.4 → 73.6%；Clean2Random 62.8 → 69.6%。後者策略與驗證器只在 clean 訓練，再到隨機環境評估。
    • Figure 6 才測約三分之一／三分之二／全時啟動的成功率—算力取捨；作者指出前四任務能保留多數改善，不能把 Table 2 全時驗證數字冒稱低觸發成本下的同等成績。
    • LIBERO：40 任務，Spatial／Object／Goal／10 四套件；\(\pi_{0.5}\) 平均 96.9 → 97.6%，StarVLA-GR00T 96.2 → 97.2%。接近飽和的均值改善小，LIBERO-10 較有區分度；不能由此推論開放環境普遍成功。

    消融：未來預測與預訓練各自有增益，但還不是機制全解¶

    Table 4 的真機平均 completion score：完整 65.5%、去掉 visual prediction objective 55.2%、predictor 不做 DROID 預訓練 59.5%；所有變體仍保留預訓練 visual encoder。

    這比只列排行榜有價值：移除世界建模監督後，單靠強編碼器與進度預測不夠；predictor 的動態先驗也有幫助。但「w/o WM」同時改變了輸出／訓練監督，不是對抽象物理理解做完美隔離；未提供 Robometer 標籤品質、task query、mask、子段數、teacher／self-forcing 的完整閉迴路消融。

    觸發品質：接觸標籤不是值得計算的真值¶

    Table 5：雙軸 trigger 的 Status AUC 0.727、與多樣本參考變異的 Spearman correlation 0.887，比單一軸好。對照包括 DINOv2 特徵加 MLP、ACE 動作段熵與兩個單軸變體。

    附錄 C 的 Status AUC 用模擬器特權接觸狀態建立標籤：接觸翻轉時刻周邊疊高斯核，截至 1，再取動作段窗口內最大值，超過 0.5 才列為二元關鍵狀態。Variance Correlation 另與較多樣本估出的變異比較，不是拿兩樣本訊號跟自己相關。

    本筆記判讀：這支持辨識接觸鄰近與候選多樣性，卻沒有直接量到「此時多算確實增加期望完成效益」。接觸可能重要但選不出更好的動作；低變異也可能是所有樣本一致犯錯。需要像 RESCUE 那樣把代理指標與反事實介入效益分開。

    五、326 ms 到底省了什麼，沒有省什麼¶

    附錄 D Table 9 比摘要更重要：基礎策略 82 ms；每輪雙樣本觸發額外 14 ms；啟動後額外 8 候選採樣 80 ms、10 候選 verifier forward 246 ms。因此不啟動的總延遲 96 ms，啟動的總延遲 422 ms；摘要的 326 ms 是額外採樣加驗證，不含 14 ms 觸發成本，更不是整輪推論時間。GPU 記憶體合計 18.5 GB。

    KV cache、並行運算、PyTorch 預編譯把該額外採樣／驗證路徑由 1261 ms 降到 326 ms；這不是世界模型天然免費。每輪平均成本還取決於啟動比例，且接觸階段可能恰好最不耐等待。

    本筆記推論：若驗證等待讓觀測過期，靜態挑選更好的段不一定得到更好的實際控制。這與 Chronos Policy 的時間有效性互補：仍需記錄觀測時間、實際生效時間與等待期間機器人的行為。本文成本表未提供動態外擾下的完整感測到致動時限保證，也不能替代 BT-Agent 的強制中斷介面。

    六、第一性原理：可選擇的候選、可預測的差異、可承受的等待¶

    最小必要狀態¶

    系統至少需要目前可辨識的物件／機器人狀態、動作對未來的影響、任務定義與進度判準，以及可承受的決策等待。只有語義辨識而沒有動作後果，排序容易空泛；只有動態而沒有任務，開與關的進度符號就可能相反。

    方法為何可能有效¶

    1. 候選覆蓋：基礎策略必須偶爾抽到好動作；驗證器只能選，不能憑空創造候選集合外的解。
    2. 資訊足夠：latent 必須保留能區分好壞候選的接觸、幾何、物件細變化。作者 §5 明列凍結編碼器可能忽略這些因素；FoveaVLA 提醒觀測解析度與幾何也會限制判分。
    3. 標籤可信：Robometer 的進度偏誤可能被 verifier 放大；好看的排序 loss 不保證物理任務真的推進。
    4. 成本值得：觸發必須抓到「可藉選擇改善」的狀態，而不只是「看起來不確定」的狀態；等待成本也必須小於選擇收益。

    失效與證據邊界¶

    • 所有候選一致錯誤：低分歧不觸發，或觸發後也無可選解；作者也明列候選多樣性有限。
    • 遮擋／細小接觸／非視覺物性：凍結視覺表徵不足時，未來預測與進度排序可能共同出錯。
    • 新任務與分布漂移：task-specific query、環境校準及驗證器訓練資料形成適用邊界；不可宣稱無訓練直接適配任何任務。
    • 代理目標：進度最大化不是碰撞風險、力矩限制或不可逆損害最小化；本文沒有安全保證。
    • 精細固定場景的結果不等於動態工廠長時間可靠性，模擬接觸標籤也不是介入必要性的真值。

    七、可複用模型與後續驗證¶

    可把計算配置拆成四張帳：候選覆蓋 → 排序可辨識性 → 介入增益 → 時間／風險成本。只改善前兩張帳，還不等於部署效益已成立。這是本筆記的跨篇整理，不是作者提供的定理。

    1. 同成本反事實：固定總 GPU 時間，比較隨機觸發、雙軸觸發與 oracle 介入；用配對狀態／種子估多採樣帶來的完成分數增量，檢查 Status AUC 是否真的預測介入效益。
    2. 延遲壓力測試：加入物件移動、外擾及感測延遲，分開記錄 96／422 ms 路徑的成功、碰撞、時間戳與過期動作；再測配合時間感知策略是否改善，而非只看離線 rank loss。
    3. 可辨識性與覆蓋：用人工進度標籤／Robometer 標籤、不同候選數與視覺解析度做受控比較；將「沒有好候選」與「有好候選卻選錯」分帳，判斷下一筆研發資源該投策略、觀測還是 verifier。

    原文章節的論證功能¶

    導論先把策略隨機性從風險翻成選擇資源；方法依序建立採樣、算力閘門與潛在進度裁判；真機段回答能否跑起來，模擬段補可重複對照，消融段檢查世界建模的必要性，觸發分析則說明閘門訊號的代理意義。附錄的評分與成本表限制了摘要最容易被誤讀的兩個數字：65.5% 不是完整成功率，326 ms 不是整輪總延遲。
