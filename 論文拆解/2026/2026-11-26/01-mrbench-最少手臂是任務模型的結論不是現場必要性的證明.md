# MRBench：最少手臂是任務模型的結論，不是現場必要性的證明

> **問題**：三隻手臂完成任務，能證明三隻都必要嗎？
> **方法**：MRScissors 讓模型寫任務需求、工具量能力，再以精確搜尋挑最小隊伍；不是讓 agents 多討論一次。
> **判斷**：它把充分性與必要性分開，但「最小」仍受工作圖、可用工具、固定基座及抓握規則限制，不能直接變成工站減機證明。

## 1. 為什麼「協作成功」沒有回答「需要多少機器人」？

若多一隻手臂也可成功，單看 success rate 會獎勵過量配置；若兩臂失敗只是抓取程式寫錯，也不能反推第三臂不可少。作者把問題改成：固定目標，改變資源，看答案會不會隨物理能力改變。

MRBench 有八項任務：四項受**同時性**限制，如同時撐兩扇彈簧門再取物；四項受**可達範圍**限制，如跨工作區接力、鋪滾槽、補骨牌與傳海綿擦拭。每項有五種配置：

- **exact**：參照配置；三臂都需要。
- **surplus**：加一臂，測試是否因為「在場」就全派上。注意不只是多出閒置臂：Rea-01 中新北側 Franka 使最小隊伍從三臂變成 W+N 兩臂。
- **shortfall**：移除必要臂，正確答案可以是不可行，而非硬編計畫。
- **swapped**：換機型；有的配置變不可行，有的因較大 reach 降成兩臂。
- **borrow**：移除一臂，提供可替代物與外觀相近但不適用的干擾物；必須量尺寸而非只認名稱。

這比固定隊伍測協調更接近換機／缺機問題。但目標不變不表示任意做法都合法：附錄 A.1 指定番茄只能滾不能搬、骨牌觸發前必須成完整一列、擦拭須持續指定時間。「必要」一開始就相對於這些程序限制。

## 2. 任務定義：把需求和提供能力的人分開

工作集合記為 $J$，手臂集合為 $A$，被動物件集合為 $P$；工作 $j$ 需要在位姿集合 $S_j$ 操作。$G$ 是必須同時執行的工作群組集合。手臂可否負責一項 act 工作，作者用：

$$
c(a,j)=1\quad\text{若}\quad \rho_a(s)\geq\delta_j\ \forall s\in S_j,\qquad w_j\leq o_a.
$$

其中 $a$ 是手臂，$\rho_a(s)$ 是工具回報在位姿 $s$ 的 IK 裕度，$\delta_j$ 是工作要求的裕度，$w_j$ 是抓握寬度，$o_a$ 是手指最大開口；$c$ 是能力關係。白話：不是型號聽起來夠大，而是每個工作點都可到、開口也夠。這裡的 IK 檢查不是完整路徑、臂間碰撞或載荷檢查（附錄 A.3）；carry 工作還要檢查交接點與端點，不能只套此單臂式。

取被動物件子集 $U\subseteq P$ 時，還須加入「把物件放到位」的工作。分配 $\sigma(j)$ 指出誰做 $j$；每個工作要有人／物能做，同一同時群組的不同工作不能共用 doer。最小支持集合定義為：

$$
\operatorname{MSS}(A,P)=\arg\min_{T\subseteq A:\,T\text{ 在工作模型內可行}} |T|.
$$

$T$ 是選用手臂集合，$|T|$ 是其數目；可以有多組同樣少的正確答案。**這是最小數量，不只是「刪任何一臂就失敗」的局部最小，也不代表特定一臂出現在所有最小解。** 被動物件不直接計入目標成本，但其安裝仍需安排；因此最少臂數不等於最低成本、最短節拍或最安全。

## 3. MRScissors 真正改了哪條資訊路徑？

輸入是目標、場景觀測、可用機型／基座與物件；輸出是可行性、最少隊伍、閒置原因、採用／拒絕物件的證據、步驟與缺失工作。流程為：

1. **盲化 prover 寫工作圖**：不給結構化的隊伍／reach，先寫工作點、同時群組、可能的替代物與尺寸界限，減少為現有隊伍「量身改寫任務」。但這不是嚴格資訊隔離：附錄 A.7 說相機仍拍到手臂，且告知最寬手指開口。故本筆記只稱結構化能力資訊盲化，不稱模型完全不知道有哪些手臂。
2. **程式填能力表**：對每臂每個工作點呼叫 `who_can`，對 carry 呼叫 `meet`，量每個替代物的必要界限。每個 cell 留工具證據，而非讓 LLM 憑觀察填可達性。短少至多 2 cm 可標 `near`，並在證書記錄；不是統計安全邊界。
3. **同一精確搜尋器枚舉**：從少臂集合往上找，回傳所有最小隊伍與證書，列出移除各臂後哪個工作無人做、替代物何以合格、無解的缺口。它證明的是輸入工作圖及能力表的結論，不替輸入語意背書。
4. **找不到隊伍才補替代物**：prover 只可新增可能替代物及其放置工作，不可在此輪任意刪改原需求；重新量測、搜尋。
5. **以不對稱舉證負擔審圖**：程式逐項翻轉工作、群組、位姿或界限，標出會改變答案的項；兩個獨立 reviewer 分查「寫太容易／太難」。修改須引用該 session 自己的工具結果；變難且影響答案的修訂可留下，變容易還須引目標原句、過 arbiter。這是在漏約束與過度約束之間調整，不是一般多數決。

**資料與訓練目標**：本文是推論時 harness／搜尋程序，不報告新的 policy 訓練資料集、微調 loss 或權重學習。最佳化目標是上述臂數；模型角色由 prompts 與工具迴圈落實，不應補成強化學習方法。

**控制迴圈**：主表為 one-shot 選隊，選好後由同 backbone 的 fresh shared executor 讀整份答案寫程式，先 `check_program` 再 Isaac 模擬，最多三次執行；執行失敗可改程式，但不回流改選隊。文中另定義 equal-budget（兩次 probe、三次 run、可修隊伍），本次讀到的主表與消融不是它的獨立結果，不混用。

相對 **LLM + solver**，搜尋器相同，改的是工作圖／能力表來源與審查；相對 SMART-LLM-style、RoCo-style、HMAS-2-style，則是由階段分工／臂間對話／中央提案與否決，換成顯式量測表加搜尋。這些是作者移植到共用介面的版本，不是原論文原設定的逐字重現。

## 4. 實驗支持了什麼，又沒支持什麼？

### 分母與資料

- Isaac Sim 4.5／Isaac Lab 2.1；Franka、PiPER、SO-101，固定基座工作桌。
- 八任務、五配置、兩難度、六 seeds，共 480 場景；其中 312 可行，14 種配置不可行。附錄特別說只有 80 個不同物理問題，seed 主要變房間、顏色、雜物與至多 1.6 cm 位移；不是 480 種獨立任務。
- 每方法／backbone 每場景選隊一次；backbones 為作者標示的 Qwen3.8-Max、Claude Sonnet 5.5，皆 high reasoning effort。本筆記未另查模型服務配置。
- team-selection accuracy 需可行性、隊伍與規定物件吻合；**Task** 指同一任務／難度／seed 的五配置全部答對，分母為 96。
- **SR** 是可行場景執行成功率；**MSS-SR** 是可行場景中「隊伍正確且執行成功」的比例，分母仍是 312，不是只在答對隊伍內計算。

### 主表、統計與代價

Table 2：MRScissors 的全場景選隊正確率為 85.4%／91.2%；各自最強 adapted baseline 為 75.0%／81.7%。但五配置全對的 Task 只有 43.8%／59.4%，顯示高平均不能取代同目標資源反事實一致性。

作者以 96 個 task-scenes 為群組做 paired bootstrap。附錄 Table 10 中，Claude 對 SMART-LLM-style 的差為 9.5 個百分點，95% interval 為 [5.4, 13.8] 個百分點。這是重抽樣程序下的差異區間，不是新工站成功率保證、不是個別配置全部顯著，更不是「真值有 95% 機率在區間內」；Table 13 的 borrow 改善區間包含零，不宜將整體優勢推到每個子類。

MSS-SR 為 46.8%／51.6%，仍有約半數可行場景未同時做到正確選隊及執行成功。Table 3 另報 **SR | right** 為 55.9%／58.8%；Oracle-team 給金標隊伍後執行 SR 為 58.7%／60.3%。但 executor 收到的是**整份答案與步驟**，因此此處改善不只歸因於挑對隊伍；金標 script 則為 100%，說明 executor 仍是瓶頸。

每場景選隊 reasoning tokens 為 421.5k／452.5k，sessions 為 3.8／3.9；比 adapted baselines 少 tokens，卻比單 session 的 LLM + solver 多。sessions 不含 executor；不能由此推整體延遲、API 費用或工站節拍。

### 消融不是「每個元件都全面加分」

Table 4 只用 Qwen3.8-Max、easy、seeds 0／4 的 80 場景：量測與盲化提高不可行辨識，卻先壓低可行辨識；加入替代物與 reviewers／arbiter 再救回可行覆蓋。完整程序 All 為 85.0%；移除 near 容忍也為 85.0%，但 swapped 與 borrow 表現不同，不能稱 near 單向改善。

用 gold graph 加 measured table 可到 97.5%；own graph 加 gold table 為 87.5%。作者據此判斷此子集中主要殘差在工作圖，而非表格。這是診斷性替換，不代表真部署能免費得到 gold graph；把 measured table 送給其他流程也未追平完整 MRScissors，故不能把全部增益只歸量測。

### 明確失效與證據邊界

- borrow 仍只 59.4%／66.7%；錯誤包括選干擾物、誤判不可行、或以為替代物還能多做別的工作，進而少派臂。
- 作者明示 privileged attachment 抓取；超過夾爪開口另有拒絕規則，未建模 grip／payload，排除單臂搬不動的重物任務。不能當成接觸力學／承載可行性的驗證。
- 金標無解在工作模型／IK 界限內成立。兩臂 script 拿掉一臂動作後失敗、或作者嘗試若干替代軌跡失敗，並不窮盡連續世界所有策略。
- 本文沒有真機驗證；完整 prompts 預告隨程式釋出，附錄只給片段。本次未查釋出狀態，未把預告寫成可直接重現。

## 5. 第一性原理：最小必要狀態，不等於最小成本系統

本筆記認為可複用的單位不是 agent 人數，而是**工作所需的不可共用能力**：哪些作用須同時成立、哪些位置由誰覆蓋、什麼被動結構能持續提供相同功能，以及誰把那個結構放上去。若漏掉「放置支撐件」這個工作，少機器人的解可能只是把成本藏到場外。

至少要保留：工作點／方向、同步需求、交接連通性、手指／幾何裕度、替代物的合格界限與放置責任。量測表把語言猜測改成可查詢證據；但若工作圖把本可串行的工作誤寫同時，solver 只會很精確地證明錯誤需求。

有效條件是需求模型覆蓋真實工作、工具誤差在界限內、替代物可安裝且維持作用。搬到現場，摩擦、負載、柔順性、路徑干涉、治具維護及改線成本都會改答案。合理順序是先驗必要能力，再比不同資源的完整成功、節拍、人工與風險，而不是把 $\min |T|$ 當作 CAPEX 最佳化。

## 6. 接回既有研究與後續驗證

與 [ACAP 的控制權交接](../2026-11-25/01-acap-並行推理縮短工期不等於控制權交接已具物理安全.md)對讀：ACAP 問「既定成員如何並行推理、誰能發命令」，MRBench 問「哪些物理成員根本需要在場」。**需要的資源、可發命令的權限、執行中是否安全，是三個不同的證明責任**，本篇未驗證兩套系統整合。

後續只追三個可推翻問題：

1. 遮掉相機中的手臂、保留／移除最大開口提示，並固定工具預算，盲化 prover 的益處還在嗎？這可分辨資訊隔離與流程改寫。
2. 加入真實夾持、payload、工具量測偏差與不同摩擦後，原最小隊伍有多少保持可行？分報「圖錯／量測錯／控制錯」，不把失敗一律算缺機。
3. 以相同隊伍、相同 executor token／run 預算，只交換 certificate steps，還有多少 MSS-SR 增益？再將治具安裝與維護算入節拍／成本，檢驗最少臂數是否真有系統收益。

**可重用判準**：一次成功證明充分；最小搜尋證明模型內必要；跨資源反事實、真物理與全成本驗收，才逐步逼近現場必要性。
