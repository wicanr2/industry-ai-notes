    Industry AI Notes｜研究與編輯規範¶

    定位¶

    這不是每日新聞與論文的摘要倉庫，而是從事件與研究方法，累積可驗證的產業判斷。每篇回答：發生了什麼、依據是什麼、機制如何運作、什麼證據會改變判斷。保留文章結構拆解與第一性原理，但不把「第一性」當成免除制度、人性與現場條件的藉口。

    收集 → 篩選 → 驗證 → 寫作 → 回收¶

    1. 收集：新聞優先官方公告、財報、政策原文、研究資料與可信報導；arXiv 保留版本 ID、作者、日期、PDF 與程式碼／資料連結（若有）。記錄候選與未入選理由，不為每日上限湊數。
    2. 去重與篩選：按事件／主張／arXiv ID 去重；同事件多家報導合併成一條證據鏈，不重複製造筆記。入選條件是新增機制、新證據或能推翻既有判斷；只有熱度而無可檢驗命題時不入選。
    3. 查證：關鍵數字追原始文件，標明日期、口徑、單位與比較基準；分清「原文事實／受訪者主張／作者推論／本筆記推論」。來源讀不到時記錄限制，不從標題補內容。
    4. 寫作：一篇一個主要問題，先給三行導讀，再展開證據和機制。優先用短段落與清單；只有表格真的更容易比較時才用表格。關聯到舊筆記與專題索引，而不複製舊段落。
    5. 回收：每日筆記按日期留作證據與脈絡；跨日同一問題匯入研究導覽與專題討論，只有能反覆使用的框架才更新思考模型。更新舊判斷時附新來源及日期，不靜默覆寫歷史判斷。

    新聞：從「文章怎麼寫」再往下追¶

    單篇至少保留原文連結、來源日期／擷取日期／可讀範圍、入選理由、文章架構地圖、第一性原理、寫法策略、可重用模型與未確定之處。新增的深入層次：

    • 核心命題與證據鏈：每項關鍵主張標註可追溯來源；若多來源說法不同，指出差異而非投票。
    • 機制與反事實：誰承受成本、誰得到選擇權、瓶頸在哪；若本文主張不成立，應觀察到什麼不同現象？
    • 時間與替代解釋：事件、宣布、量產、營收及制度生效不是同一時間；列至少一個合理競爭解釋。
    • 追蹤訊號：用 1–3 個可觀察指標及觀察期限，說明什麼會提高／降低信心；不能取得的資料明說。

    不得把「作者意圖」說成已證實心理事實；文章架構分析應用「可能希望讀者……」等可辯護語氣。

    論文：讀出方法，而不只讀導論¶

    優先閱讀摘要、導論、方法、實驗與限制的相關章節；時間或可取得性有限時，至少讀摘要、導論及方法原文，才可寫「方法論述」。若方法無法取得，改記候選，不發布成方法已驗證的完整筆記；必要時發布「導論速覽」並明顯標記未讀方法與未驗證結果。每篇明載實際閱讀範圍、版本與擷取日期。

    方法論述按問題而非照章節翻譯：輸入／輸出及任務定義 → 系統／模型流程 → 訓練資料與目標函數 → 推論或控制迴圈 → 與基線真正不同之處 → 消融／評估如何測試機制。缺失項目標「論文未提供／本次未讀」，不可推測填空。公式首次出現用 GitHub LaTeX 與白話說明符號、邊界及量測含義；區分作者聲稱與筆記判斷。結果要附資料集、指標、基線、公平比較與失效場景；未讀實驗時不可寫成已驗證結果。最後保留第一性原理：最小必要狀態、物理／計算／資料約束、方法為何可能有效及何時失效。

    節奏與庫務¶

    既有排程不變：新聞每日 08:00、論文每日 09:00（Asia/Taipei）；新聞台灣最多 3 篇、國外有價值才最多 2 篇；論文每日最多 2 篇，不強制湊滿。每日發文與每月／定期整理是不同工作，不用提高發文頻率來換整理效率。根 README 僅作短入口，日期索引保存候選與當天脈絡，跨日索引只保留精選的可重用線索。發布流程見本機 scripts/deploy_pages_local.sh；不得用 GitHub Actions 代替本機建置。舊筆記不因規格升級而假裝曾閱讀方法或查證來源；需要補讀時明確標示補讀日期。
