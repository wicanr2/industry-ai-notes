# 數位員工不是一個模型，而是權限、成本與責任的編排

## 為什麼選這篇

「AI Agent」很容易被寫成模型能力又進一步，但這篇真正有價值的地方，是把企業落地所需的幾個異質問題放在同一張圖上：地端與雲端算力、模型路由、ERP／CRM 串接、資料主權、Token 成本、系統整合，以及人與代理人的協作。它讓我看見，所謂數位員工並不是一個更會回答問題的模型，而是一套能被授權去改變企業狀態的工作系統。

同時，文章主要依據廠商活動與公司說法，15% 效率提升和 30% 預估缺乏量測方法。這正適合練習：如何從產品發布稿的上升敘事裡，抽出可驗證的能力帳本，而不把願景直接當成成果。

## 一句話拆解

當 AI 從「產生答案」跨到「完成流程」，稀缺資源便從模型智力轉為可控的系統權限、正確的模型分工、可追溯的責任鏈，以及跨部門整合能力。

## 第一性原理拆解

### 1. 最基本的問題：企業買的不是文字，而是狀態改變

AI 助理輸出一段文字，錯誤通常停在螢幕上；Agent 若能寫入 CRM、核准表單、回覆客戶或觸發採購，錯誤就會改變金流、權限與承諾。因此「能不能回答」與「能不能安全執行」是兩個完全不同的產品問題。

一個可執行代理人的最低閉環是：

**取得情境 → 判斷任務 → 選擇工具／模型 → 取得權限 → 執行 → 驗證結果 → 留下稽核軌跡 → 必要時交還人類。**

文章清楚談了前半段的模型與系統串接，後半段的驗證、回滾、稽核和責任歸屬則著墨較少。這正是「數位員工」最不該被名稱遮掉的部分。

### 2. 約束不是算力單一瓶頸，而是五種預算同時存在

- **金錢預算**：每個流程能承受多少推論與整合成本。
- **延遲預算**：客服即時回應與月底報表可容忍的等待不同。
- **風險預算**：摘要錯一句與付款錯一筆，損害尺度不同。
- **資料邊界**：個資、醫療、金融或營業秘密能否離開地端。
- **人類注意力**：若每一步都要求覆核，自動化只把工作改名。

因此 Right Model 不能只按「任務難度」路由，也要按資料敏感度、可逆性、影響金額與驗證成本路由。

### 3. 因果鏈

單點 AI 工具增加
→ 各部門形成不同模型、資料與權限孤島
→ 真正跨系統流程仍靠人搬運
→ 平臺嘗試統一身分、工具、路由與治理
→ AI 才能從建議跨到執行
→ 但執行權越大，錯誤半徑與治理負擔越大
→ 平臺價值最終取決於「自主程度增加時，事故率是否仍可控」。

### 4. 誘因與權力關係

- 電信商希望把網路、機房、GPU、模型與企業服務疊成長約，而非只賣連線。
- 系統整合商掌握舊系統、流程與產業語境；這些知識往往比模型本身更難替換。
- 部門主管想要效率，但資安、法遵和 IT 承擔事故責任，會要求更細的權限與稽核。
- 員工既是使用者，也是工作被重新切分的一方；「98% 導入」不等於信任、熟練或淨生產力提升。

台灣大與精誠的互補，實際上是**基礎設施控制權**與**企業流程知識**的結盟。

### 5. 稀缺資源

真正稀缺的可能不是 GPU，而是：乾淨且有權使用的資料、可被 API 操作的舊系統、懂流程例外的人、可接受的權限設計，以及能證明產出正確的評測資料。

## 寫法與敘事策略

文章以「助理 → 數位員工」作為主軸，這是一個很有效的角色隱喻。它讓讀者立即理解能力升級，卻也會把軟體的機率性與組織責任擬人化：員工有職務說明、訓練、主管、績效、懲處和法律責任；Agent 若沒有對應機制，只有名稱像員工。

3R 是可記憶的三詞框架，將複雜架構壓縮成「適當」的資源配置。文中再用台客語語音交給專用模型、高難度決策交給雲端大模型，使抽象路由變得具體。後段的 98%、15%、30% 數字扮演證據錨點，但三者口徑不同：採用率、已觀察效率、未來預估不應被讀成同一條成熟度曲線。

結尾加入精誠的 IT、台灣大的 CT 與日本客服市場，讓文章從產品功能轉成通路及併購協同故事。不過主要聲音都來自供應商，沒有客戶端、資安端或第一線員工的反證。

## 可抽象成的思考模型

### 「代理人六帳本」

評估企業 Agent，不先問用了哪個模型，而依序問：

1. **任務帳本**：它完成哪個可觀察的工作結果？
2. **權限帳本**：能讀什麼、寫什麼、花多少錢、誰核准？
3. **路由帳本**：何時用規則、小模型、大模型或人類？
4. **風險帳本**：錯誤是否可逆、影響半徑多大、如何回滾？
5. **證據帳本**：效率、品質與事故率的基準線及樣本數是什麼？
6. **責任帳本**：供應商、IT、部門主管、操作者各自承擔什麼？

只有六本帳能對起來，「數位員工」才不只是產品命名。

### 路由的簡化判斷式

**任務淨價值 = 節省的人力與等待成本 − 推論／整合成本 − 預期錯誤損失 − 覆核成本。**

最強模型不一定讓淨價值最高；最佳架構是把不同任務送到淨價值最高且符合資料邊界的處理路徑。

## 我可以放進資料庫的筆記

- AI 從回答走向執行時，產品核心會從生成品質轉向權限與責任設計。
- 模型路由不是單純省 Token，而是同時配置成本、延遲、資料主權與錯誤半徑。
- 企業舊系統的 API 可操作性，是 Agent 普及速度的隱性上限。
- 「全地端」解決資料位置問題，不自動解決錯誤決策、內部越權與供應鏈風險。
- 採用率、使用率、流程覆蓋率、時間節省、品質與事故率必須分開量測。
- 電信商加系統整合商的組合，本質是基礎設施與流程知識的雙邊控制。
- 數位員工若沒有職務邊界、主管、稽核與退場機制，只是被擬人化的自動化腳本。

## 仍不確定的地方

- 15% 效率提升的基準、樣本、任務範圍與品質控制未公開；30% 是預估，不是已驗證結果。
- 98% 員工「導入」是帳號開通、曾使用、週活躍，或已進入核心流程，文章沒有說明。
- MyAgent 的記憶隔離、工具權限、提示注入防護、人工覆核、回滾與稽核能力未具體揭露。
- 智慧路由由規則、分類模型還是代理人自行決定，以及路由錯誤如何評測，仍不清楚。
- 台灣大與精誠的合作能否從客製專案轉成可重複部署的產品毛利，尚無證據。
- 日本 AI 客服是下一步計畫，尚不能視為客戶訂單或市場驗證。
